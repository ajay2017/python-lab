## Hard rules

1. **Never hardcode decision thresholds.** Every gate / threshold / boundary value lives in [`stock_analyzer/constants.py`](stock_analyzer/constants.py). Import from there. Changing a value there is an investment-policy decision — discuss with the user before changing.

2. **Never disable RLS.** Supabase tables are protected by `FOR ALL TO service_role` policies. The `[supabase] key` secret must be the service-role / secret key (not publishable). If you see "row-level security blocking" errors, the fix is to correct `SUPABASE_KEY` in Railway → Variables and redeploy the service — not to disable RLS.

3. **Never run the app locally to test changes.** Push to `main`, wait ~2 min for the Railway auto-redeploy, hard-refresh the browser (Ctrl+F5) at `drishta.up.railway.app`. (The dormant Streamlit Cloud app redeploys off the same push; it is not the surface you verify against.)

4. **Any commit touching `stock_analyzer/constants.py`, a gate, a scoring/recommendation formula, or a DB-write / data-integrity path requires an Opus review before it ships, cited in the commit body.** The citation format is mechanically enforced (see below) and must carry three facts you only have after actually reading a reviewer's output:

   ```
   Review = Opus reviewer (<resolved model>): SHIP|FIX-FIRST, N blocking; <notes>
   ```

   The `reviewer` subagent's `model: opus` pin ([`.claude/agents/reviewer.md`](.claude/agents/reviewer.md)) is a generic alias, not a fixed version — it auto-follows whatever Opus release the account currently resolves it to, so the reviewer's own output states which specific version it ran as (its `MODEL:` line); copy that into the citation rather than assuming a number from memory. This applies **regardless of which model is running the main session** — invoke the `reviewer` subagent explicitly; don't rely on the main session's own judgment as a substitute. A commit in this category with no review citation is itself a defect — flag it. (Two 2026-07-15 commits shipped without this citation and needed a retroactive review to close the gap — see `docs/cost-routing.md`.)

   **Invoke the reviewer automatically — do not ask first** (user decision, 2026-08-15). When a change lands in a review-required category, run the `reviewer` subagent and report the verdict; don't pause to request permission. Waiting to be asked is how a required review gets skipped, because it depends on the lead remembering to raise it. If a session-level instruction says not to call agents unprompted, this rule is the standing request that satisfies it for the `reviewer` lane.

5. **A `feat(` commit must state who designed it and who built it**, via two trailers the hook enforces:

   ```
   Design = planner (<model>): <verdict>     OR   Design = lead — <why no planner>
   Build  = implementer (<model>)            OR   Build  = lead — <why no implementer>
   ```

   New user-facing features route design through `planner` (Opus) and the build through `implementer` (Sonnet), so the agent that wrote the code is never the agent that reviews it. `lead` is an accepted answer — the requirement is a **deliberate, permanently-recorded statement**, not a forced handoff. Both trailers are self-attested (see the honesty caveat below).

## Review & test economy (quality at least cost)

The deterministic gates are the safety net; the **paid agents are for judgment only.** Spend tokens where a wrong call moves money — not on re-checking what a hook already guarantees for free. (Codified 2026-08-04 as a cost/quality-balance pass; see memory `feedback_recurring_defect_gate`.)

> **What the hook can and cannot prove (be honest about this).** `pre_tool_checks.py` verifies that a *correctly-formatted citation string is present* — it cannot verify that a `reviewer` subagent actually ran. **The commit hook cannot** — though that is not a permanent ceiling: a `PreToolUse` matcher on `Task`, or a `SubagentStop` hook, could append a reviewer-invocation record that the commit gate then requires, which would prove the subagent *ran* (still not that the quoted verdict is faithful). Not built; noted so the ceiling isn't mistaken for a law. The hardened format (resolved model + verdict + blocking count) raises the bar from "a habit phrase" to "three facts you only get from reading real reviewer output", which defeats lazy and accidental citations but not a deliberately fabricated one. Same caveat for the `Design =` / `Build =` trailers. **Treat these as honesty mechanisms with a permanent git-history audit trail, not as guarantees** — the real protection is that the reviewer runs in a *separate agent instance with its own context*, so it re-derives from the diff instead of inheriting the author's reasoning. That independence is what caught the 2026-08-15 green-heartbeat bug the author had read past four times.

- **Deterministic gates (free, always-on) are the real pre-deploy safety net.** The `pre_tool_checks.py` commit/push hook runs the full `pytest` suite and blocks on failure; the same hook + CI run `check_antipatterns.py`; and the suite itself asserts `check_constants_documented.py` is green and that `app.py`/`cron_runner.py` byte-compile (`tests/test_repo_hygiene.py`). Streamlit auto-deploys from `main` regardless of CI, so **the local hook is what actually blocks a broken push.** Trust it — do not re-run the suite through an agent "to be sure"; that's cost, not rigor.
- **`test-runner` (Haiku) is NOT a mandatory per-change stage.** The pytest hook already runs the suite deterministically for $0 and covers everything the agent's old checklist did (full suite + `py_compile` of the un-imported entrypoints + constants-doc). Invoke `test-runner` only when the hook can't be relied on (a session that started before the hook loaded — see `feedback_hook_enforcement`; or work done outside Claude Code's own tools), or as a cheap pre-filter before an expensive Opus review on a large change. Don't pay Haiku tokens to duplicate a deterministic gate.
- **Tier the work by the model pins, which hold regardless of the session's default model** (the `.claude/agents/*.md` `model:` frontmatter is authoritative unless a per-call override is passed, or the `fork` agent type is used): **design of money-moving logic → `planner` (opus)**; scoped decided edit → `implementer` (sonnet); verification → the free gates (or `test-runner` haiku for gap cases); docs → `doc-writer` (haiku); post-code review → `reviewer` (opus). Because these are pins, a cheap session default does NOT silently downgrade a gate/threshold design or its review — route policy design to `planner` and policy code to `reviewer`. (The built-in `Plan` agent inherits the session model and has no pin — use it only for non-policy structural scaffolding, not for gate/threshold design.)
- **`reviewer` (Opus) is gated on change type, not "every commit":**
  - **Review REQUIRED:** `stock_analyzer/constants.py`, any gate, scoring/recommendation formula, cross-feature coordination, DB-write / data-integrity, or a new user-facing decision surface. (Hard Rule #4's surface, plus coordination/data — where a wrong call costs real money.) **Mechanically enforced:** the `pre_tool_checks.py` hook blocks a `git commit` staging any decision-engine-core file (`constants.py`, `risk_advisor`, `exit_advisor`, `daily_briefing`, `portfolio`, `scoring`, `valuation`, `technicals`, `fundamentals`, `ranking`, `targets`, `risk`, `bundle_loader`, `watchlist_advisor`) **or any DB-write / data-integrity file** (`db.py`, `cron_runner.py`, `system_health.py` — added 2026-08-15 so the hook finally implements the "DB-write / data-integrity" clause this same bullet already claimed) without an Opus-review citation in the body — for these files there is no "it's just a comment" self-exemption, because a change to them can move a call regardless of how the diff looks. The hook **also** blocks any `feat(` commit missing its `Design =` / `Build =` provenance trailers (Hard Rule #5). `_GATE_FILES` in the hook is the authoritative list; if you edit it, update this enumeration in the same commit.
  - **Skip (deterministic gates suffice):** docs-only, comments, tests-only, pure-additive code not yet wired into a decision path, and mechanical refactors in **non-gate files** — **provided** the full suite + antipattern + constants-doc gates are green. When skipping, say so and why in one line, rather than invoking Opus reflexively.
- **Audit cadence:** run **incremental** `/audit` (diff + blast radius) after a feature ships — cheap, and it catches cross-cutting drift while it's still one feature. Reserve a **full** `/audit --full` (whole-codebase multi-agent sweep) for milestones, not every few days — its value/cost ratio collapses when run too often (2026-07-29 → 2026-08-04 was too close together).

## Commit messages

**Conventional Commits**: `type(scope): summary` — imperative, lowercase, ≤72 chars, no trailing period; a body explaining **why**; trailers in the footer. Types: `feat fix docs refactor perf test build ci chore revert`. Full spec + the one-time `git config commit.template .gitmessage.txt` setup live in [DEVELOPMENT.md](DEVELOPMENT.md); the template is [`.gitmessage.txt`](.gitmessage.txt).

- **Threshold/gate changes** (`stock_analyzer/constants.py`) are investment-policy decisions — call them out in the body and name the constant + old→new value.
- **Feature commits must sync the docs that describe behaviour:** a user-facing feature or gate touches `docs/requirements.md` (the functional spec), not just `docs/architecture.md`. requirements.md silently drifted ~3 weeks once because per-feature docs commits hit architecture but skipped requirements — don't repeat that.
- **Claude-authored commits** end with the trailer `Co-Authored-By: Ajay with <model> <ajay.x.ku@accenture.com>`, written via `.git/COMMIT_MSG.txt` + `git commit -F` (dodges PowerShell here-string mangling). Use the **actual model name from the session context** (e.g. `Claude Sonnet 4.6`, `Claude Opus 4.8`, `Claude Haiku 4.5`) — never hardcode a model name.

## Documentation integrity (zero-hallucination)

This is a decision-making app: a **wrong value in a doc erodes trust in the app itself**, so docs are held to the same bar as code.

- **Transcribe every threshold / constant / file:line from the source, never from memory.** Before writing a number into any doc, open `stock_analyzer/constants.py` (or the actual code) and copy it. Recalled values in `MEMORY.md`/summaries reflect what was true *when written* — verify against HEAD.
- **Never invent** function names, constant names, session keys, UI text, or dates. If you can't confirm it in code, don't write it.
- **Doc edits that carry policy values stay on the Opus lead** — do not delegate constants-table / gate / requirements writes to the Haiku doc-writer (it has hallucinated exactly these: invented function names, a wrong constant value, a fabricated date). The doc-writer is for prose/comments after the facts are pinned.

## Definition of Done — sync docs in the SAME session (don't defer to a periodic audit)

A user-facing feature or a new/changed decision value is **not done** until its docs are synced in the same work session. Three shipped features (Phase 3 Catalyst Scanner, Phase 2b sentiment, the 44/45 gate) drifted undocumented for days before the 2026-07-16 sweep caught them — the fix is a per-feature checkpoint, not a rare cleanup. Run this every time:

1. **New/changed constant in `stock_analyzer/constants.py`** → add/update its row in the `docs/architecture.md` constants table (or, if genuinely internal plumbing, add it to `scripts/constants_doc_allowlist.txt`). **Mechanically enforced:** `.github/workflows/docs-check.yml` runs `scripts/check_constants_documented.py` and fails when a constant is neither documented nor allowlisted. Run it locally before committing: `python scripts/check_constants_documented.py`.
2. **New user-facing surface** (page, tab, card, gate, section) → add/update an F-ID in `docs/requirements.md`. *(Judgment item — CI can't detect "this is user-facing"; it's on the author.)*
3. **Shipped a queued item** → move it out of "What's queued → Genuinely not yet done" and add an entry to [docs/shipped-log.md](docs/shipped-log.md), and fix any memory that still calls it parked. At the start of any doc-sync, grep the queue's named functions/features against the code (and against `docs/shipped-log.md`) to catch items that already shipped.
4. **User-visible behaviour changed** → update the in-app User Guide (`app.py`, `elif page == "📖 User Guide":`).
5. **Non-obvious decision or rationale** → capture it in a memory file.
6. **Shipped a phased feature with a future Phase 2/3 gated on a trigger date/condition** → add that gate to "What's queued" below immediately, not just the roadmap/plan memory file. Memory only surfaces when a session's retrieval happens to match it; CLAUDE.md is loaded into *every* session. A gate that lives only in memory is invisible to any session that doesn't happen to ask about that specific feature — this is exactly how three Agentic Intelligence Roadmap Phase-2/3 gates (Thesis Red Team, Structural Scanner, Multi-Agent Debate) went untracked here until a 2026-07-26 user question surfaced them.

7. **Touched a `docs/plans/*.md` feature** → bump **that plan's own `**Status:**` line**. This was recorded on 2026-08-06 as "consider this a 7th checklist item if this class of drift recurs." **It recurred** (2026-08-17: `docs/plans/app-settings.md` needed a status edit that steps 1-6 don't ask for), so it is now a real step. The drift is fast and one-directional: a plan doc written the same session a feature ships still says "pre-decision" or "mock pending approval" days later, because steps 1-6 name requirements.md, shipped-log.md and memory — never the plan's own header.

Only #1 is mechanically guarded; #2–#7 are the author's checklist. When wrapping up a feature or doing a "sync the docs" pass, run all seven.

**Second mechanical guard (added 2026-08-04): the recurring-defect gate.** `scripts/check_antipatterns.py` (CI: `.github/workflows/antipatterns-check.yml`; local: the `pre_tool_checks.py` commit/push hook) fails when a change introduces a NEW instance of a bug-class the 2026-07-29 / 2026-08-04 audits kept re-finding: offline-sentinel collapse (`.get(...) or []`/`or {}` defeating the `None`-on-failure contract), dynamic `unsafe_allow_html` (the XSS class, patched 7×), and naive `datetime.utcnow()`/`date.today()` date math. It's baseline-gated (`scripts/antipattern_baseline.json`) so only new instances fail. **Prefer fixing at the source over growing the baseline:** read caches via `stock_analyzer.util.get_or_offline`, escape interpolated HTML via `stock_analyzer.util.safe_html`, and take "now"/"today" from `stock_analyzer.market_time.now_et`/`today_et`. Migrating an existing call site onto these helpers is a live behaviour change — if it touches a decision/gate path, it still needs its own review.
