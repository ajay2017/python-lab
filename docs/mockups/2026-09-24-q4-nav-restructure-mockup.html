The rule this needs, so navigating never hides your own location: whichever group contains the CURRENTLY ACTIVE page auto-force-expands on that render, regardless of its remembered collapsed/expanded state — shown above, PORTFOLIO is pre-opened simulating a landing on Risk Analysis while PORTFOLIO was still collapsed. Without this rule, you could click into a page and its own sidebar highlight would be invisible inside a collapsed section — confusing, not just inconsistent. Streamlit-side this is simple: each group's expanded/collapsed state lives in st.session_state (default: only "MAIN" and "TRACK RECORD" start True), and the render loop ORs in "is this the active page's group" before deciding whether to show it expanded — the user's own manual toggle is still remembered for next time, this rule just overrides it for the one render where it matters.
This is a genuinely separate implementation piece from the regroup itself (a new per-group collapse mechanism touching ALL 6 groups, not just the new one) — bigger blast radius than Q4's original "just move some pages" scope, but still pure UI/interaction, zero gate/content/constant touch. Confirm you want it bundled into the same commit, or shipped as its own immediate follow-up once the regroup itself is live.
Decisions needed from you
1. Group label: "TRACK RECORD" (Option A) vs "LEARN" (Option B)? Note: "TRACK RECORD" needs the code to key off just the word "TRACK" (first word of the label) for its accent/icon lookup — a minor maintainer quirk, not a user-visible difference. "LEARN" is a single word so it doesn't have that quirk, and reads a bit softer/broader (fits Predictive Analytics' "learn where your edge comes from" framing and Model Lab's validation-harness role slightly better).
2. Accent color: rose #f472b6 (Option A — maximally distinct from all 5 existing colors) vs muted slate #94a3b8 (Option B — an "archival" tone, but risks reading as "disabled/greyed out").
3. Does 🔬 Model Lab belong here? It's the one genuinely borderline page — it forward-forecasts 20-day volatility, so it's not strictly "did a past call work" like the other 6. The planner recommends moving it anyway (same DNA: owner-only, quarantined, "feeds no gate, no recommendation, no composite — a measurement harness," which fits "retrospective/validation" better than it fits RESEARCH's live decision tools). If you disagree, it can simply stay in RESEARCH with zero impact on the rest of this design.
