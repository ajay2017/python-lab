## What is true at HEAD (corrections to the brief)

"Unreadable" = something inside the build raises (an unexpected FRED payload escaping `_fp.current_and_previous` / `_apply_reading` :963-992, or an odd `port_df` in `_affected_tickers` :536), neither caught today → a code fault, not an outage; ≈ zero frequency.

## Design

- **Grow Today: a whole-day hold** on the existing `entry_hold` early return. Order: `tone_unread` → bear (keeps its G-23 row) → **`macro_unread`** → `tone_not_today`. Whole-day because an unread calendar can't say which sector, and market-wide events (FOMC / GDP) hold every name anyway. ETFs held too (already held under any imminent event: `macro_sector_gate.decide` :102-106). Adds held (Q1). `entry_hold` is already read generically by `gate_ledger.build_suppression_rows` (:120), `sizing_path.held_add_verdict` (:361, incl. the Rebalancer), `hold_reasons.leads_note` / `adds_paused_note`, the redeploy headline (Home + Signals), `grow_header_view` / `grow_count_text`, the cron diag (:964-976). A per-name late hold was rejected (every pick path would need a leak-proof hold). `macro_unread` sits before `tone_not_today` so a pre-open banner never says "returns after the 9:30 open" while the calendar is still broken; the macro hold names both conditions.
- **📋 Watchlist / 09:45 Watchlist email / 📈 Analysis: a per-name abstention.** `check_macro`'s "unchecked" state becomes a hold, check `macro_unread`; covers every card incl. ETFs; one banner per page.
- **Binding:** `_ABSTENTION_CHECKS = frozenset({"tone_unread", "macro_unread"})`; `macro_unknown_sector` stays out (no existing binding changes). With an unread map G-28 can't fire; the G-29 bear binding (and its ledger row) is the one to protect.
- **A FRED failure counts as "read"** (Q3): the static dates are the source of truth; with `released` False the same-day gate stays on until the release time passes (entry_eligibility.py:144-153).
- **Protective paths unchanged:** on None, `_act_today` (:3458) and `_review_list` (:4192) use `or []`, so stop / deterioration / risk-off cards stay; only the macro-specific sell-side cards go quiet (sibling MacroTrimUnread).

## Owner decisions (recommended default first)

- **Q1** A broken calendar holds adds as well as new picks and ETF picks? **Default yes** (a pre-event trim normally stops an add; "recommend nothing"). Cost: on a broken-calendar day adds are stricter than on a real CPI week. Alternative needs a per-lane hold (more code, more leak paths). Whether adds get the macro check at all stays with N-C.
- **Q2** A scan / 11:30 run with an unreadable calendar turns the lane red + sends the failure email? **Default yes** (tone U3 precedent). It's a code fault, so up to ≈ 3 failure emails a day until fixed.
- **Q3** A FRED outage or odd FRED data counts as "calendar read" (static dates only, no buy hold)? **Default yes**; needs a guard around the FRED step in `build_macro_calendar` (gate file).
- **Q4** When the hand-typed dates run out (rows end in 2027; System Trust ⑤ amber 2027-07-31), hold buys? **Default: not in C4m**; a dated Waiting row MacroCoverageExpiredOpen, decided before 2027-07-31 or made moot by #33.

No constant changes value; none is added.
