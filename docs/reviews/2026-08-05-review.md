## 4. High-priority issues

**`scripts/check_antipatterns.py:103-109` — the OFFLINE_SENTINEL_COLLAPSE detector only catches the `x.get(...) or []`/`or {}` boolean-or form; it never looks at the two-argument `x.get(key, [])`/`x.get(key, {})` default-argument form**, which collapses "key genuinely absent" into "checked, empty" in exactly the same way. This is not a hypothetical gap: `stock_analyzer/daily_briefing.py:561` (`market_context.get("leading_sectors", [])`) and `:1554` (`rec.get("redeploy_sectors", [])`) are live instances of this exact shape in a decision-engine-core file, invisible to the gate and absent from its baseline. **Currently benign** — every constructor of `market_context` (verified: `app.py:4432,4435,4599`; `daily_briefing.py:2427`; `headless_alert_engine.py:334,349`) always sets `"leading_sectors"` explicitly, so the default never actually fires today — but the gate provides zero protection if a future code path ever omits the key to signal "computation failed," which is precisely the scenario this whole gate exists to catch.
**Why it matters:** CLAUDE.md treats this gate as "the real pre-deploy safety net" for this bug class specifically. A detector that's narrower than its own name is a false sense of security, not a smaller version of the same protection.
**Fix:** in `_Visitor.visit_Call` (or a new visitor method), also flag a `.get()` call with 2 positional args where `args[1]` is an empty-container literal (reuse the existing `_is_empty_container` helper).

## 5. Medium-priority issues

- **`scripts/check_antipatterns.py:75-91` (`_is_dynamic_html`)** — only flags `ast.Call` nodes whose `func` is a dotted `.format()`/`.join()` attribute; a call to a bare-name helper function (`ast.Name`) always falls through to "not dynamic," even though the helper may build interpolated markup internally. Live instance: `app.py`'s `_tr_evidence_row()` (`app.py:22727-22760`) interpolates `t['ticker']`, `t['action']`, `t['shares']`, `t['price']`, `t['outcome_pnl']`, `t['outcome_pct']` into HTML unescaped (only one field, `_sig_seen_clip`, is `html.escape`d) and is passed to `st.markdown(..., unsafe_allow_html=True)` at 7+ call sites (e.g. `app.py:22869,22884,22894`) — none of them appear in the antipattern baseline because the gate never saw this shape as dynamic. Exploitability is low today (ticker/action/shares are sourced from the user's own logged trades, not external input, and this is a single-user app — effectively self-XSS at worst), but it's a live, uncaught instance of exactly the bug class this gate exists to close.
  **Fix:** extend `_is_dynamic_html` to also flag `ast.Call` where `func` is a bare `ast.Name` (any locally-defined helper), not only dotted `.format()`/`.join()`.

- **`stock_analyzer/trade_analytics.py:213-224` (`_build_overtrading_stats`)** — the naive-`utcnow()` fix moved `current_month` to ET (`_dt.now(_ET).strftime(...)`, line 223) but left the historical `month_str` bucketing (line 218, derived from `_parse_dt(traded_at)` via `pd.to_datetime`, which preserves whatever offset Supabase's `traded_at` ISO string carries — effectively UTC) on the old timezone. This is a **new** mismatch the partial fix introduced — before the fix, both sides agreed (both naive/UTC-ish); now they don't. In the last ~4-5 hours of an ET trading day (already past midnight UTC), a live trade lands in a UTC "next month" bucket while `current_month` still names "this month" in ET, so `current_count` silently misses it — undercounting exactly the after-hours overtrading spike this feature exists to catch.
  **Fix:** bucket `month_str` via an explicit ET conversion (`d.astimezone(ET).strftime(...)`) so both sides of the comparison agree, ideally routed through the shared `stock_analyzer.market_time` helper rather than this module's own ad-hoc timezone handling.

- **`stock_analyzer/daily_briefing.py:1391-1392`** — the new TRIM-directive suggested-quantity text (`DETERIORATION_TRIM_SUGGESTED_PCT`, shipped this session) computes `max(1, int(d['shares'] * DETERIORATION_TRIM_SUGGESTED_PCT / 100.0))`. `d['shares']` is itself `int(shares)`-truncated upstream (`exit_advisor.py:334`), so a genuine fractional-share holding under 1 total share (plausible via the Robinhood-CSV broker-import path) reports `d['shares'] == 0`, while the `max(1, ...)` floor still forces the suggested quantity to `1` — producing a self-contradictory directive: *"an approximate 25% reduction (1 of 0 shares)."*
  **Fix:** guard the parenthetical behind `if d['shares'] > 0`, or drop the share-count clause entirely when `d['shares']` truncates to 0 (fall back to the qualitative "trim into the weakness" phrasing this directive used before the session's fix).

## 8. Systemic observations

- **The recurring-defect gate's own detectors are narrower than the bug classes they're named after.** Both gaps found (§4, §5) are for the *idiomatic, common* form of each bug class (`.get(key, default)` is the single most common way to read a dict key with a fallback in Python; a bare helper function building markup is a completely ordinary refactor of an inline f-string) — not an obscure edge case. A gate whose coverage silently excludes the common case of what it's supposed to catch is worth auditing itself whenever a new bug-class rule is added, not just trusting the AST visitor's first draft.
- **`int(shares)`/`int(some_float)` truncation-to-zero is now a recurring blind spot for fractional-share holdings**, not a one-off. This is the second time an int-truncation issue has surfaced around `shares` in user-facing copy (the other being `exit_advisor.py:334`'s own truncation, which this session's new TRIM-quantity clause then compounded). Worth a dedicated grep for every `int(`-cast of a shares/quantity value that feeds directly into user-facing text, not just patching this one site.
- **Large mechanical UX/vocabulary-rename batches continue to hold up well** under independent scrutiny (see §7) — this validates continuing to use the line-slice/reassemble + independent-diff-verification methodology this project has now used repeatedly, rather than treating each new large rename as a fresh risk to relitigate.
