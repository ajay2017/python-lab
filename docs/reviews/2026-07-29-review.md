## 3. High-priority issues

### H1. Two live, disagreeing `detect_macro_regime()` implementations
**Files:** `stock_analyzer/macro.py:76-153` (old, ETF-return-based, 3 signals: TLT/SPY/VIX) vs `stock_analyzer/macro_calendar.py:732-1040` (new, FRED-based, 7 signals).
**Fact.** Both are still live: `app.py:193` imports the old one as `detect_macro_regime`, called only at `app.py:14707` (the manual-button "Macro Signals" panel, feeding `portfolio_macro_exposure()`/`RATE_SENSITIVITY`/`REGIME_FAVORED` sector rotation at `14736`). `app.py:170` aliases the new one `detect_macro_regime_fred`, used at lines `5228, 10531, 10977, 24995` (Home, Risk Analysis, Regime Fit, regime-conditional targets). The two use different label vocabularies and signal sets and can legitimately disagree on the same day. This is a latent, not guaranteed-same-screen, contradiction — the old panel is behind a manual load button — but it is two functions sharing a name with diverging logic and no cross-reference or disclaimer either direction.
**Why it matters:** a user who loads the Macro Signals panel and separately checks Risk Analysis's Regime Fit diagnostic could see two contradictory regime reads with no explanation.
**Fix:** retire `macro.py::detect_macro_regime`/rewire the Macro Signals panel onto the FRED-based function, or rename one so it can never be import-confused, and add a note on the legacy panel that it uses a different, non-authoritative read.

### H2. `macro_calendar.detect_macro_regime()` hardcodes 6 of its 7 signal thresholds inline
**File:** `stock_analyzer/macro_calendar.py`.
**Fact, Opus-confirmed exactly as listed:** Fed Funds trend ±0.05 (`783,787`); 2s10s spread −0.25/0.0/0.75 (`829,833,836`); unemployment Δ 0.3/−0.2 (`852,856`); HY credit spread 600/450/300bps (`875,879,883`); SPY 20d return ±5.0 (`909,913`); VIX 30/20/15 (`924,928,931`); `winning_score <= 1` fallback (`968`). Only the CPI ladder (`REGIME_CPI_*`) is imported from `constants.py`.
**Why it matters:** this function decides the regime label feeding Home/Risk Analysis and `regime_targets.py`'s beta ceilings/cash floors — a genuine investment-policy boundary per Hard Rule #1, currently invisible to `scripts/check_constants_documented.py` since it can only catch undocumented *named* constants, not inline literals.
**Fix:** promote each signal family to a named constant (e.g. `REGIME_FEDFUNDS_TREND_PP`, `REGIME_2S10S_INVERTED_PP`/`_STEEP_PP`, `REGIME_UNEMP_DELTA_UP_PP`, `REGIME_HY_SPREAD_STRESS_BP`/`_ELEVATED_BP`/`_CALM_BP`, `REGIME_SPY_20D_BULL_PCT`/`_BEAR_PCT`, `REGIME_VIX_STRESS`/`_CALM`, `REGIME_WINNING_SCORE_MIN`).

### H3. `portfolio.py`'s hardcoded decision thresholds — one already realized as drift, several more never centralized
**Files:** `stock_analyzer/portfolio.py:405,410` (gap-to-stop `gap<3`/`gap<7`), `:424,429` (`pnl>15`/`pnl<-8`), `:519` (`pnl>20`), `:543-544` (`w<5 and score>70`, an 8%-target-weight literal), `:567` (`gap<5`).
**Fact, Opus-confirmed and widened from the first pass:** `constants.py` already has `POSITION_AT_RISK_GAP_PCT=3.0` (coincidentally matches the `3`) and `APPROACHING_STOP_GAP_PCT=8.0` — which does **not** match the `7` used at `portfolio.py:410`. This is a real, already-realized instance of "near-duplicate constants silently drifting apart," not a theoretical risk. The `score>70` at `:543` matches neither `COMPOSITE_BUY=65` nor `COMPOSITE_STRONG_BUY=75` and may be dead weight (the adjacent `"Strong Buy" in signal` check already implies ≥75, making `score>70` a redundant sub-condition worth understanding before touching).
**Why it matters:** a position at gap=7.5% reads "approaching stop" on Home/Review-Before-Close (using the correct `APPROACHING_STOP_GAP_PCT=8`) but only a milder tier on Signals & Advice using this unsourced `7`.
**Fix:** replace the bare literals with `POSITION_AT_RISK_GAP_PCT`/`APPROACHING_STOP_GAP_PCT` (or a new dedicated constant if intent genuinely differs), and name the rest (`ALERT_PNL_PROFIT_TAKE_PCT`, `ALERT_PNL_STOP_LOSS_PCT`, etc.) per Hard Rule #1.

### H4. Three independent, uncoordinated "should this position be trimmed/exited" computations
**Files:** `stock_analyzer/portfolio.py:424-433` (alerts), `stock_analyzer/portfolio.py:519-588` (rebalance_actions), `stock_analyzer/exit_advisor.py:150-206` (`classify_deterioration_tier`).
**Fact, Opus-confirmed.** Only `exit_advisor.classify_deterioration_tier` is fully centralized (imports `POSITION_SETTLING_DAYS`, `DETERIORATION_CONFIRM_REQUIRED`, `DETERIORATION_EXIT_DOLLAR_LOSS`, `DETERIORATION_WATCH_DD_PCT`). The other two independently compute a similar "sell/trim" signal from different data (composite `Signal` string + raw P&L vs. drawdown/trend/relative-strength) and feed three different surfaces: `_alert_list_cache`→Signals & Advice, `_actions_cache`→Risk Analysis, and the Daily Brief. None of the three consult each other or `decision_bucket.reduce_call_tickers()`.
**Why it matters:** a name can sit in exit_advisor's WATCH/TRIM/EXIT tier (composite still "Hold," by design) while `alerts()`/`rebalance_actions()` say nothing, or vice versa — the user gets a contradictory read of the same position depending which page they're on.
**Fix:** at minimum, annotate `alerts()`/`rebalance_actions()` bearish items with the ticker's current deterioration tier (if any); longer-term, fold the older logic into or gate it behind `exit_advisor`'s tiering so there's one canonical answer.

### H5. `debate_agent.py` — NaN/inf can reach the Bull/Bear/Judge LLM prompt unguarded
**File:** `stock_analyzer/debate_agent.py` — `build_entry_corpus()` lines ~191-196 (`current_price`), ~239-251 (`momentum_5d_pct`, `momentum_20d_pct`); `build_exit_corpus()` ~374-388; consumer `_format_corpus()` ~71-98.
**Fact, Opus-confirmed.** `build_entry_corpus` wraps each value in a bare `try/except Exception` with no `math.isfinite` check. `build_exit_corpus` guards `math.isnan` but **not** `math.isinf`. `_format_corpus` checks only `is not None` — NaN/inf are "not None," so a degenerate value renders as literal `"+nan%"`/`"$nan"` straight into the Haiku prompt.
**Why it matters:** the debate's whole value proposition ("cite specific numbers, do not fabricate") is undermined if the model is handed and echoes a literal `nan`. The sibling feature `thesis_red_team.py`'s equivalent caller (`app.py:28251-28258`) correctly scrubs every value with `math.isfinite()` — this feature didn't get the same treatment.
**Fix:** replace the bare `except: pass` blocks with an explicit `math.isfinite()` check before assignment, in both corpus builders, matching the existing Thesis Red Team pattern.

### H6. `daily_briefing.py` — a risk-off "TRIM" card can co-exist with a "not an action yet" WATCH card for the same ticker, same render
**File:** `stock_analyzer/daily_briefing.py:2236-2269` (`build_daily_briefing`).
**Fact, Opus-confirmed.** Order of operations: `deterioration` computed (2236) → `act` built (2238) → `review` finalized (2240, deduped only against `act` as it existed then) → `_reduced` built (2251-2257) from `act` plus **only** review items whose `action.type` is `TRIM_AND_TIGHTEN`/`TRIM_TO_TARGET`/`PROTECTIVE_TRIM` — WATCH-type review items (deterioration WATCH, `TIGHTEN_ONLY`, earnings/news WATCH) are never added — → `exit_advisor.assess_risk_off_derisk(..., exclude_tickers=_reduced)` runs (2258) and its picks are appended to `act` (2264), **after** `review` was already frozen, with no re-dedup on return (2276).
**Why it matters:** a ticker carrying only a WATCH-type review card can also be picked by the beta-contribution-ranked risk-off trim, producing a same-Brief contradiction: "early deterioration — not an action yet" (Review) next to "Trim ~X% now — risk-off" (Act Today). This only arms when the book is fragile AND the market is risk-off, so it's intermittent, but it is a genuine same-render contradiction when it fires — the exact class of bug the SHOP same-day buy/sell whiplash fix (shipped yesterday, F-39h/F-221/G-21) was written to close, recurring on a different pair of surfaces.
**Fix:** include every ticker carrying *any* review action (not just the three TRIM types) in `_reduced` before calling `assess_risk_off_derisk`, or compute risk-off before `_review_list` and feed the merged act list into its existing `_act_tickers` dedup.

### H7. XSS regression class — 4 new live `unsafe_allow_html=True` sites rendering unescaped external/user/LLM text
**Fact, Opus-confirmed all four.** This project has fixed this exact bug class twice before (news headlines, 2026-05-27; notes/thesis fields, 2026-06-28) — fixing the instance did not fix the class:
- `app.py:5263-5278` — Pre-Market Stance's Haiku narrative (built from real external news headlines) rendered unescaped.
- `app.py:986-989` — the shared `_render_debate_result()` helper renders `_tr.get('text','')` (a Bull/Bear LLM argument) unescaped; affects 3 call sites (entry-debate ~6288, exit-debate "Challenge This Exit" ~6793, and the Debate Log tab ~28455) — one fix closes all three.
- `app.py:26353-26360` — "Your thesis" on 🧠 AI Insights → Positions renders the raw `user_thesis` free-text field unescaped — **the identical field is correctly escaped elsewhere** (Home's Review-Before-Close card, `app.py:7331-7336`, via `_html.escape`). This is the strongest of the four: the exact field class the 2026-06-28 audit already fixed, missed at this one render site.
- `app.py:27724-27728` — Analyst Coverage's `company` field (LLM-extracted from pasted research, or user-edited) rendered unescaped. Medium, not High — bounded by short field length and single-user curation.
**Fix:** wrap each with `_html.escape(...)` (the codebase already has this helper in active use at 9+ other sites) before interpolation.

### H8. `intelligence_report.py:74` `_pct()` — missing NaN guard, a live recurrence of an already-patched bug
**File:** `stock_analyzer/intelligence_report.py:74-80` (feeds prompt text at `282-284, 315`, e.g. `_pct(w.get('spy_pct'))`).
**Fact, Opus-confirmed.** `f"{float(v):+.1f}%"` with only an `is None` guard — `float('nan')` passes through and renders `"nan%"`. This is the identical SPY/alpha data shape that caused a prior, already-fixed bug (`debrief_advisor._pct`, `notify._pct_cell`, commit `374a7d5`, "treat NaN SPY return as unavailable, not '+nan%'") — the fix was applied to two sibling formatters but not this third one, and because this one feeds an LLM prompt (not just display), a NaN here can surface as a fabricated-looking number in AI-generated report text.
**Fix:** add the same `isinstance(v, float) and v != v` (or `math.isfinite`) guard used in the two sibling formatters; consider consolidating all three into one shared formatter to close the class permanently.

### H9. `app.py:7775-7828` — "Thesis Under Pressure" (F-196 Phase 3, shipped 2026-07-28) baseline loop is not memoized and fires on every Home rerun
**File:** `app.py:7775-7828`, shipped less than 24 hours before this audit ran.
**Fact, Opus-confirmed in class; the first-pass magnitude was corrected.** This block sits outside the `_home_synth_cache` signature-based memoization (`app.py:3846-3979`) that gates the rest of the Brief's expensive work, and `db.load_thesis_erosion_cache()` (`db.py:2429`) has no `@st.cache_data` — so it re-runs on every single Streamlit rerun of Home (any button click anywhere on the page), not once per day. **Corrected magnitude:** the today-row check (line 7793, `if not _tup_row or ... is None: continue`) runs *before* the baseline walk-back loop, so for the common case (a portfolio that hasn't visited the Red Team tab today), each ticker misses after exactly **one** call — roughly N calls per rerun (N = held tickers), not N×11. The up-to-11-call walk-back only applies to tickers that *already have* a scored today-row (i.e., ones the user just visited the Red Team tab for) and lack a baseline within the last 10 trading days — a narrower, just-shipped-feature window. Still a real defect: an un-memoized, N-uncached-Supabase-calls-per-rerun loop, just not the worst-case ~165 first described.
**Why it matters:** this is a genuine architecture gap in code that had two rounds of Opus plan review and full test-suite verification before shipping yesterday — a useful, non-defensive reminder that per-feature review doesn't substitute for a periodic full-codebase sweep, which is exactly why this audit exists.
**Fix:** fold the today-row lookups into the existing `_home_synth_cache` signature/bundle (already tracks a signature keyed off held tickers + date), or batch into one `.in_("ticker", tickers).eq("score_date", today)` query instead of N individual round-trips.

## 6. Patterns worth keeping

- **`exit_advisor.py`** is the cleanest file in the scoring/gate scope: every threshold imported from `constants.py` by name, docstrings explain *why* each floor/ceiling/window exists (including non-obvious interactions like ATR-scaling + ceiling-cap, and "deep EXIT bypasses settling grace"), and the pure-scalar core is fully decoupled from the pandas extraction layer for testability. Model this scope should be pulled toward.
- **`decision_bucket.py`'s `_ticker()`/`_is_reduce()` canonical-resolver pattern** correctly solves the "which ticker does this item really mean" split-brain problem (macro items carry `ticker=None` + `action.trim_ticker`). The one gap found (a non-adopting consumer in `daily_briefing.py`) is a consumer that hasn't adopted it yet, not a flaw in the resolver.
- **`concentration.py`'s `assess_add_concentration`/`gating_denominator`** are exemplary: pure, parametrized (constants passed in by the caller, zero embedded policy), with a "tighter-of-both, cash never loosens" rule documented like a policy memo.
- **`constants.py`'s provenance discipline** — nearly every constant's comment states which surface reads it and whether it gates vs. displays; several recent entries explicitly narrate having been extracted from inline literals during a prior Hard-Rule-#1 sweep (exactly the self-correcting behavior this audit exists to reinforce — it just hasn't reached `targets.py`/`macro.py`/`ranking.py` yet).
- **A two-layer fabrication guard (ticker-must-exist-in-corpus + claimed-value-must-verify-against-real-data)** is consistently applied across every LLM-touching diagnostic module (`thesis_cluster`, `missed_opportunity`, `catalyst_stress`, `structural_scanner`), structurally preventing hallucinated tickers/claims from reaching the UI.
- **`_grow_today`/`_buy_candidates`/`_review_list`'s** heavily-commented cross-referencing consistently cites the *specific real historical incident* (FSLR, SHOP, TSLA, INTC, DELL, AVGO, MSFT) that motivated each gate — this is what made H6 findable at all, and is worth continuing.
- **The read-only-viewer design is genuine defense-in-depth, not just cosmetic:** every write function in `db.py` independently checks the global `_READONLY` flag and no-ops, so a missed UI `disabled=` gate cannot actually mutate owner data (though it can still trigger LLM cost — see §8).
- **The "button + day-level DB cache" combo for LLM/expensive calls** is applied with near-100% consistency across the whole app outside the one un-memoized loop in H9 — no other auto-fire-on-rerun landmine was found anywhere in Summary, Risk Analysis, Intelligence, Portfolio Overview, Recommendations History, AI Insights, Trade Journal, or Predictive Analytics.
- **`cron_runner.py`'s dedup-state-saved-only-on-real-send-or-legitimate-empty-run rule** is applied uniformly across all 4 alert lanes — the right anti-pattern-avoidance for a headless notifier.
- **`_json_safe()`'s NaN/inf/numpy-scalar coercion before every JSONB write**, and **API-key redaction (`_redact_url`) before any exception is logged/raised** in the provider adapters, are both good habits applied consistently.
- **The User Guide is otherwise highly accurate** — 8+ spot-checked numeric/threshold claims (composite weights, gate values, ATR-stop ratchet tiers, VIX levels, sector caps) all matched `constants.py` exactly. H10 is a real, isolated miss, not a sign of broader drift.
- **`_pending_page` → `nav_page` indirection** is applied with 100% consistency across ~38 navigation sites in `app.py` — zero direct `nav_page` assignments found outside the one sanctioned consumption block.
- **`_home_synth_cache`'s signature-tuple memoization** is a strong pattern (single explicit signature gating the entire expensive rebuild, with an explicit hit-path re-publish so downstream pages never see stale coordination caches) — the irony that F-196 Phase 3 (H9) didn't join this pattern is itself the clearest evidence for why it should be the default, not the exception, for new Home additions.

## 7. Systemic observations

1. **The dominant risk pattern in this audit is threshold/gate logic recurring in 3+ independently-maintained places for the same underlying question**, with no shared source of truth: "should this be trimmed/exited" (H4, 3 implementations), "what's the current macro regime" (H1, 2 implementations), "what's the most recent BUY row for this ticker" (3-4 near-duplicate implementations across `daily_briefing.py`, `app.py`, `thesis_cluster.py`), and float/percent formatting (24+ and 3 reimplementations respectively). Several have already silently drifted (H3); others agree only by coincidence today (macro.py's VIX literals vs. `RISK_OFF_VIX_LEVEL`). This is wider than any single finding and is the one thing worth a deliberate follow-up: an inventory of "the same decision, computed more than once."

2. **NaN/inf guards are inconsistently applied even within files that clearly know the pattern.** `debate_agent.py`'s exit-corpus builder guards `NaN` but not `inf` in the same line of code that guards `NaN`. This project has hit and fixed this exact bug class multiple times (weekly debrief email, Thesis Red Team's 6-round review history) — the fix keeps landing on the specific file that broke, not on a shared numeric-coercion helper that would close the class once. H5, H8, and the Medium-tier `intraday_entry.py` finding are three fresh instances of a bug this codebase has already paid down before.

3. **Read-only-viewer gating is excellent for data-integrity (DB writes) but inconsistent for cost-exposure (LLM calls).** 30+ genuine DB-mutation buttons correctly carry `disabled=readonly`, backstopped by `db.py`'s independent `_READONLY` no-op — real defense-in-depth. But at least 6 distinct LLM-cost-triggering buttons across 3 different pages (Home, Portfolio Overview/Intelligence, Trade Journal) lack the same guard, and the corresponding cache-save functions are *deliberately* not `_READONLY`-gated (correctly, since the cached result itself is recomputable, not owner data) — meaning there is currently no backstop at all for the cost dimension, only for the data-integrity dimension. This is a coherent, real gap across the whole app, not a one-off oversight.

4. **The XSS-class bug (H7) has now been found and fixed three separate times** (news headlines; notes/thesis; and now 4 more sites) — each fix closed the specific instance, never a shared rendering helper. A single `escape`-by-default HTML-card helper (wrapping the common `st.markdown(f"<div>...</div>", unsafe_allow_html=True)` idiom already used 40+ times across the file) would close this class permanently instead of requiring a fourth future audit to find a fifth instance.

5. **This audit found a real defect in code shipped less than 24 hours before the audit ran** (H9, F-196 Phase 3) — smaller than first estimated once independently re-verified, but real. Two rounds of Opus plan review, a full 1,160-test pytest pass, and live production validation all preceded that ship, and none of them caught the missing memoization, because none of them were structured to ask "does this new Home addition participate in the existing full-page memoization pattern?" That question is exactly what a periodic full sweep is for, and is the strongest argument for keeping this cadence rather than relying solely on per-feature review.
