# DRISHTA — UX Audit
*2026-08-04 · Full app · app.py (32,043 lines, read in 6 page-aligned chunks) + 55 stock_analyzer/ advisor & display modules (3 groups) · 9 parallel research passes, synthesized by the lead*

---

## Executive Summary

Individual features are well-built: the "never silently filter," "awareness only, never gates," and offline-vs-checked-empty conventions are followed consistently almost everywhere, error/empty states are worded rather than blank, and several genuinely strong interaction patterns (evidence-first action cards, two-step destructive confirms, fail-open LLM handling) repeat cleanly across the app. The single biggest opportunity — confirmed independently by all 9 research passes without prompting — is **severity/verdict vocabulary fragmentation**: at least 10 distinct severity taxonomies and several outright word collisions ("WATCH," "critical," "Confirmed," "OK," "Intact," "Disciplined") each carry different meanings on different pages, including two pages meant to be read together. A handful of concrete, verified gaps also need direct fixes: a privacy-masking gap on the Account page, a raw Python constant name leaking into user-facing copy, one real verdict-collapse bug in the Debate feature, several un-constants-ified gate thresholds (a couple of which provably duplicate an existing named constant by coincidence), and one silent-filter violation of the app's own stated rule. None of this is a "redesign" problem — it's the natural residue of ~87 independently-built modules shipped at high velocity; a canonical severity enum + shared label map, reused everywhere, would resolve most of it at once.

## Critical Issues (fix before launch)

### C1 — Account page privacy-masking is incomplete
- **Location**: `app.py:25066-25479` (💰 Account page)
- **Problem**: KPI tiles (Total Account Value, Invested Equity, Net Cash, etc.) are correctly wrapped in the `_m()` masking helper when privacy mode is on. But the Capital Trend chart directly below (y-axis `tickprefix="$"`, hover templates at `25382`/`25392`/`25410`) and its auto-generated narration paragraph (`_d()` helper, `25444-25479`) render **raw, unmasked dollar figures**. A user who toggles privacy mode sees masked tiles at the top of the page and fully exposed dollar amounts in the chart and prose right below them.
- **Recommendation**: Route the chart's hover/axis values and the narration's dollar interpolations through the same `_m()`/masking check the KPI tiles already use.

### C2 — The User Guide's own claim about the color system is false, in the same file range
- **Location**: `app.py:27149-27172` (User Guide "🚦 Signal severity — what the colors mean") vs. `app.py:26320-26326` and `26063-26068` (Economic Calendar Post-Event / Pre-Event Playbook)
- **Problem**: The User Guide states plainly *"The app uses three color bands across all pages"* (red/amber/green) and gives a page-by-page mapping table — but the Post-Event Results tab colors `HOLD` blue (`#3b82f6`) and the Pre-Event Playbook colors it grey, a 4th and 5th color the Guide's own table doesn't mention or reconcile. The Guide's mapping table also never lists the Economic Calendar Playbook/Post-Event tabs at all.
- **Recommendation**: Either fold `HOLD` into one of the three canonical colors (e.g. grey→green-adjacent "clear") on both Calendar sub-tabs, or update the User Guide's claim to say "three bands plus a neutral HOLD state" and add the missing tabs to its own mapping table.

### C3 — A raw Python constant name leaks verbatim into user-facing copy
- **Location**: `app.py:24781` (📊 Predictive Analytics)
- **Problem**: A caption reads *"Bands/horizons below n={PREDICTIVE_MIN_BAND_N} (`PREDICTIVE_MIN_BAND_N`) are still shown."* — the backticked identifier is the literal Python constant name, not a formatted value.
- **Recommendation**: Drop the backticked identifier; the interpolated number alone already conveys the threshold.

### C4 — A real debate disagreement and an infrastructure failure are indistinguishable to the user
- **Location**: `stock_analyzer/debate_agent.py:511-534`
- **Problem**: When the Haiku judge-verdict call fails or returns unparseable output, the function silently defaults `verdict: "contested"` with `bull_case_score`/`bear_case_score`/`grounded` all `None`. A genuine 50/50 contested debate and an infrastructure failure produce the identical `verdict` string on screen — only the null scores (invisible unless specifically checked) distinguish them.
- **Recommendation**: Return a distinct sentinel (e.g. `verdict: None, error: "judge_failed"`) instead of overloading `"contested"` for both a real disagreement and a failure.

### C5 — "Confirmed" means two unrelated things in the intelligence layer
- **Location**: `stock_analyzer/thesis_cluster.py:307-311` vs. `stock_analyzer/intelligence_report.py:305`
- **Problem**: `thesis_cluster.py`'s `state: "confirmed"` means "this thesis matches a real price-correlation cluster." `intelligence_report.py` uses `"Confirmed = the App's actual recommendations"` for a completely different concept — a cross-source-verified engine recommendation. Both are intelligence-layer, LLM-adjacent surfaces.
- **Recommendation**: Qualify each ("Cluster Confirmed" / "Cross-Check Confirmed") rather than the bare word.

### C6 — "OK" is used both for "no action needed" and for "act now, this is a buy signal"
- **Location**: `stock_analyzer/watchlist_advisor.py:45-59` vs. `stock_analyzer/risk_advisor.py:288,366,511`
- **Problem**: `watchlist_advisor.py` maps its single most time-sensitive, actionable state (`ENTER_NOW`) to `priority: "OK"` — identical to how `risk_advisor.py` uses `"OK"` to mean nothing needs attention. `watchlist_advisor.py`'s own code comment (`:55-59`) acknowledges the display order is manually re-ranked away from this field specifically because of the mismatch — but the raw field remains available to any other consumer and is misleading on its face.
- **Recommendation**: Never reuse "OK" for a buy-now signal; give `ENTER_NOW` its own priority label.

### C7 — Several REDUCE/ADD-gating thresholds are un-constants-ified, and at least two provably duplicate real constants by coincidence
- **Location**: `stock_analyzer/earnings_advisor.py:209`; `stock_analyzer/macro_playbook.py:300-304`
- **Problem** (both verified directly against `constants.py`): `earnings_advisor.py:209` hardcodes `if score < 44 and weight >= 5:` gating a REDUCE recommendation — the file already imports `COMPOSITE_BUY`/`COMPOSITE_STRONG_BUY` from `constants.py` but not `COMPOSITE_HOLD`, whose real value is exactly `44`. Separately, `macro_playbook.py:300-304` defines `_PROTECT_BEAR=1.5`, `_WATCH_WEIGHT=8.0`, `_WATCH_BEAR=1.0`, `_OPP_SCORE=68.0`, `_OPP_BULL=1.5` as bare module-local literals — in the *same code block* where the two sibling thresholds (`_PROTECT_WEIGHT`, `_PROTECT_SCORE`) were already migrated to alias `SINGLE_NAME_CEILING`/`COMPOSITE_HOLD`, with a comment explaining a real prior bug this fixed ("the previous literal 18.0 contradicted SINGLE_NAME_CEILING... importing makes the link explicit"). The fix was applied to 2 of 6 thresholds in the block; the other 4 were left exactly as risky as the one that already caused a bug.
- **Recommendation**: Import `COMPOSITE_HOLD` in `earnings_advisor.py` and use the name, not the literal. Finish the `macro_playbook.py` migration for the remaining 4 thresholds the same way the first 2 were fixed.

### C8 — A silent suppression violates the app's own "never silently filter" rule
- **Location**: `app.py:11344-11346` (🔗 Risk Analysis, Stress Testing → defensive-pick finder)
- **Problem**: Defensive-pick candidates below `COMPOSITE_HOLD` are `continue`-skipped with no visible count or banner — contrast with the sibling zero-results case a few lines above (`11298-11301`), which *does* show an explicit "No unowned defensive picks found" message. CLAUDE.md's own hard rule requires a visible banner for every UI suppression.
- **Recommendation**: Add a caption stating how many candidates were filtered by the composite floor, matching the sibling empty-state's transparency.

### C9 — Unsourced "institutional authority" statistics are presented as flat fact in advisory copy
- **Location**: `stock_analyzer/earnings_advisor.py:245-249,200-204`; `stock_analyzer/rebalancer.py:213-220,316-322`; `stock_analyzer/perf_advisor.py:253-262,330-337`
- **Problem**: A recurring `institutional_lens` template repeats specific, uncited statistics across three modules as if computed by the app — e.g. *"stocks with negative pre-earnings revisions miss consensus at twice the rate of those with positive revisions"* and *"systematic rebalancing... adds approximately 0.5–1.0% annually versus a drift portfolio."* This app holds its own documentation to a zero-hallucination bar; user-facing advisory copy that a retail investor may act on deserves at least the same scrutiny.
- **Recommendation**: Either cite a real source for each specific figure, or soften the language to a general principle without a fabricated-precision number.

### C10 — An icon collision blurs the app's own awareness/actionable boundary
- **Location**: `stock_analyzer/sentiment_velocity.py:135` vs. `stock_analyzer/quick_research.py:82-91`
- **Problem**: ✅ is used for `"Sentiment improving"` — explicitly awareness-only per this app's sentiment policy — and also for `"Normal Entry Conditions"`, an actual entry-timing verdict meaning it's fine to buy now. The same glyph spans "FYI, don't act on this" and "you may act on this," in an app whose entire operating posture depends on that line staying clear.
- **Recommendation**: Reserve ✅ for one side of that line; give the other a distinct icon.

## Improvements (high value, not blocking)

### I1 — Home is one long unconditional scroll with no unified alert treatment
- **Location**: `app.py:3663-9061`
- **Problem**: Command Center → Today's Brief → 🌙 Evening Debrief → 🤖 AI Snapshot render as four+ full-width sections with no tabs, and up to four independently-coded warning banners (price cross-check disagreement, Day Shock, stock-split detected, structural-cluster alert) can all stack above the Command Center on one load, each with its own visual treatment.
- **Recommendation**: Consider a single "alerts stack" component for the banner cluster; evaluate whether Evening Debrief/AI Snapshot (added after the page was deliberately de-tabbed) now warrant their own tab again.

### I2 — Portfolio Overview's Performance tab has no internal structure
- **Location**: `app.py:14220-15167`
- **Problem**: Six distinct analyses (SPY performance, Performance Diagnostics, P&L Waterfall, Sector Rotation Heatmap, Real-Sector Benchmark Tilt, Rankings) are separated only by code comments, not by any UI-visible break — likely the densest single tab in the app.
- **Recommendation**: Nested sub-tabs or a jump-menu for this one tab.

### I3 — TRIM directives give no quantity while every other reduce-type does
- **Location**: `stock_analyzer/daily_briefing.py:1382-1389`; `stock_analyzer/exit_advisor.py:339-343`
- **Problem**: EXIT directives say "exit most/all of N shares"; TRIM says only "trim into the weakness" with no share count or percentage — by design per the code comment, but it's the one card type in the "reduce" family without a concrete number.
- **Recommendation**: Add an approximate floor (e.g. "trim 20–30%") even if less precise than EXIT's exact count.

### I4 — Several MONITOR/WATCH-type follow-ups rely entirely on user memory
- **Location**: Custom Price Alerts (`app.py:9917-9995`, re-renders identically forever, no dismiss/snooze); Thesis Red Team (recomputes silently once/day, no "this changed since you looked" alert); Sentiment Momentum "tighten the stop" cards (`app.py:13909`, no follow-up link)
- **Problem**: None of these have a reminder mechanism if the user simply doesn't revisit that tab.
- **Recommendation**: At minimum, a "changed since your last visit" flag on re-render for the highest-stakes of these (Thesis Red Team, price alerts).

### I5 — Two word-collisions sit on the exact page pairs meant to be read together
- **Location**: "Intact" — Thesis Review status (`app.py:27560-27561`) vs. Red Team erosion label (`app.py:29609-29614`), both on AI Insights. "Disciplined" — Decision-Quality grade-B (`app.py:31004-31007`) vs. Conviction-Alignment high score (`app.py:31558-31566`), both on My Edge.
- **Problem**: These aren't distant modules that happen to share a word — they're designed to be cross-referenced by the same user on the same page, so the collision risk is maximal exactly where it matters most.
- **Recommendation**: Rename one side of each pair.

### I6 — `macro_playbook.py` names the same trim action differently pre- vs. post-event, in the same file
- **Location**: `stock_analyzer/macro_playbook.py:319-337` (pre-event: `PROTECT`) vs. `:714-745` (post-event: `REDUCE`)
- **Problem**: Both represent selling part of a position around a macro print; the module uses two different verbs for the identical underlying action depending on timing.
- **Recommendation**: Pick one verb for "reduce around this event" and use it in both branches.

### I7 — The same R:R threshold is expressed three different ways on pages meant to agree
- **Location**: `app.py:17884` (literal text "R/R ≥ 2×"), `app.py:17643` (dynamically formats `RR_ENTRY_MIN`), `app.py:18000` (separately hardcoded 2.5/1.5 quality bands), `app.py:19129` (separately hardcoded 2.0 on Watchlist)
- **Problem**: `RR_ENTRY_MIN = 2.0` currently matches the literal text, so nothing is wrong today — but three of these four are hand-written duplicates that would silently drift from the fourth (the one that actually imports the constant) if the policy value ever changes.
- **Recommendation**: Format all four from `RR_ENTRY_MIN` directly.

### I8 — Destructive actions are inconsistently confirmed
- **Location**: Single-click, no confirm: analyst-coverage row delete (`app.py:29101-29108`), Portfolio Q&A "Clear conversation" (`app.py:29784-29786`). Two-step confirm: Watchlist remove (`18768-18782`), Trade History delete (`21481-21497`), BUY/SELL cards (`19622-19650`).
- **Problem**: Most of the app follows a clean warning + "Yes, X"/"Cancel" pattern for anything destructive; these two don't.
- **Recommendation**: Apply the same two-step pattern to both.

### I9 — Two parallel macro-regime taxonomies ship simultaneously
- **Location**: `stock_analyzer/macro_calendar.py` (`rate_cut`/`inflation_fight`/`recession_fear`/`stagflation_risk`/`neutral`, FRED-based) vs. `stock_analyzer/macro.py` legacy (`rising_rates`/`falling_rates`/`risk_off`/`risk_on`/`neutral`, ETF-proxy-based)
- **Problem**: A prior fix already resolved an import-name collision between these (per the module's own docstring), but the two disjoint label vocabularies for "what's the macro regime right now" can both still reach the user for the same underlying question.
- **Recommendation**: A UI-level disambiguating sub-label ("FRED read" vs. "ETF-proxy read") beyond the existing code-only disclaimer.

### I10 — Whether a user gets a Back button depends on which page they came from
- **Location**: `app.py:19496-19506` (Watchlist → Analysis, sets `_nav_origin`) vs. `app.py:19273-19275` (Compare → Analysis, doesn't)
- **Problem**: Landing on Analysis from Watchlist gives a working Back button; landing from Compare doesn't, for the identical "deep dive on this ticker" action.
- **Recommendation**: Set `_nav_origin` on Compare's buttons too.

### I11 — Same-day recommendations suggest identical ETFs with two different sizing ranges
- **Location**: `stock_analyzer/risk_advisor.py:263-265` (beta rec: "adding 8–10%") vs. `:428-429` (volatility rec: "Add 8–12%")
- **Problem**: Both recommend Healthcare XLV / Consumer Staples XLP / Utilities XLU as diversifiers, in the same module, with different ranges — a user seeing both cards the same day gets two different numbers for the same action.
- **Recommendation**: Reuse one shared sizing range constant across both branches.

### I12 — Internal roadmap phase numbers render verbatim in section headers
- **Location**: `app.py:9206` ("🔍 Coherence audit (Phase 4)"), `app.py:9254` ("📊 Track record (Phase 2 + 3)")
- **Problem**: Development-phase numbering is meant for the build log, not the end user.
- **Recommendation**: Drop the "(Phase N)" suffix from user-facing headers; keep it in code comments only.

### I13 — `risk_advisor.py` returns a bare `[]` for two different failure reasons
- **Location**: `stock_analyzer/risk_advisor.py:93-94,138-139`
- **Problem**: "No portfolio data" and "invalid portfolio value" both return `[]`, indistinguishable from each other and, at the letter of this project's own producer convention, not clearly distinguishable from "checked, genuinely nothing to flag" either (though a healthy portfolio in practice always gets at least an `ok_*` card).
- **Recommendation**: Confirm the app.py call site gates on a separate `is None`-style check rather than trusting this function's raw return; if not, return `None` for the two failure cases per the project's own convention.

### I14 — Erosion-tier band boundaries shown to the user don't trace to any named constant
- **Location**: `app.py:29581-29582` ("0–24 Intact · 25–49 Softening · 50–74 Eroding · 75–100 Breaking")
- **Problem**: Verified against `constants.py`: only `THESIS_EROSION_HAIKU_MIN`(30)/`BRIEF_MIN`(50)/`BRIEF_JUMP`(15) exist — none of the four band boundaries shown in this caption match a named constant. Contrast with the Decision-Quality grade caption two tabs over, which correctly derives its boundaries from `DECISION_QUALITY_GRADE_A/B/C/D`.
- **Recommendation**: If these boundaries are real gates somewhere in `thesis_red_team.py`'s erosion-scoring logic, name them in `constants.py` and format this caption from the names.

## Patterns worth preserving

Every one of the 9 research passes independently surfaced the same strengths, worth protecting during any remediation pass:

- **"Never fabricate a neutral/default on missing data"** — explicit, correct handling across `quick_research.py`, `cross_asset.py`, `macro.py`'s regime detection, `perf_advisor.py`, and `debrief_advisor.py`. A genuinely offline/insufficient-data state is textually distinct from a checked-and-calm one nearly everywhere this matters.
- **Evidence-first action-card labeling** — "WHAT TRIGGERED THIS" / "The Problem" / "Recommended Action" / "Expected Outcome," reused across Signals & Advice and Risk Analysis, including an explicit "AI can make mistakes, double-check" disclaimer on LLM-sourced evidence.
- **Two-step destructive confirms** (warning + "Yes, X"/"Cancel") — Watchlist remove, Trade History delete, BUY/SELL confirmation cards, Account cash-flow ledger delete.
- **Fail-open, never raise, on any LLM/API failure** — universal across every LLM-touching module checked (`portfolio_qa.py`, `debate_agent.py`, `structural_scanner.py`, `missed_opportunity.py`, `thesis_cluster.py`, `analyst_intel.py`, `intelligence_report.py`, `thesis_advisor.py`, `premortem_advisor.py`, `thesis_red_team.py`).
- **Bounded dataframe/chart height regardless of row count** — `height=min(CAP, 60 + 35*len(rows))`-style guards reused across Trade Review, Recommendations History, Predictive Analytics, and the Sankey/heatmap charts on Portfolio Overview.
- **Cross-page "deep dive" navigation via `_pending_page` + `st.rerun()`** — used correctly and consistently everywhere checked; zero direct `nav_page` writes found outside the one sanctioned consumption block.
- **Threshold values interpolated from `constants.py` into LLM system prompts and tooltips** (`analyst_intel.py`, `intelligence_report.py`, Composite Score tooltip) rather than hand-transcribed — the correct pattern that most of the Critical/Improvement findings above are asking the exceptions to match.
