## 2. Findings detail

### F1 — Bare `except Exception` silently wipes `_ac_map` (`app.py` ~11434) · **CONFIRMED HIGH**

**The problem:** The avg-cost map is built inside a single `try/except Exception: _ac_map = {}` block. Any non-numeric value in `holdings_df["Avg Cost ($)"]` (e.g., a cell reading `"N/A"`) raises `ValueError` during `float(...)`, the outer handler resets `_ac_map = {}`, and every subsequent ticker gets `_avg = 0.0`. With `_avg == 0`, the guard `_avg > 0` is False, `_prot = _base` (raw ATR stop), and manual stops in the `[ATR, ratchet_floor)` gap are accepted by Analysis but rejected by `build_portfolio_df` — reopening the split-brain the gate was written to close.

```python
# Current (broken)
try:
    _hdf = st.session_state.get("holdings_df")
    if _hdf is not None and not _hdf.empty:
        for _, _h in _hdf.iterrows():
            _ac_map[str(_h.get("Ticker", "")).upper()] = float(_h.get("Avg Cost ($)") or 0)
except Exception:
    _ac_map = {}   # ← wipes the entire map on any single-row error
```

**Fix:** Move the exception handling inside the per-row loop so a bad row is skipped, not the whole map:

```python
_ac_map = {}
_hdf = st.session_state.get("holdings_df")
if _hdf is not None and not _hdf.empty:
    for _, _h in _hdf.iterrows():
        try:
            _ac_map[str(_h.get("Ticker", "")).upper()] = float(_h.get("Avg Cost ($)") or 0)
        except (TypeError, ValueError):
            pass
```

### F2 — `protective_stop` called with live price; `build_portfolio_df` used synthesis price (`app.py` ~11456) · **CONFIRMED MED**

**The problem:** The live-price merge at lines 11412–11416 updates `results[t]["current_price"]` to the latest 60s refresh (T2). `protective_stop(_price, _avg, _base)` then computes `_prot` from T2. `build_portfolio_df` computed its stop from the synthesis-frozen price (T1). If the stock ticks up intraday and crosses a ratchet tier between T1 and T2 (e.g., +9.8% at synthesis → +10.5% live), `_prot` is higher on Analysis than in the Brief. A manual stop the Brief accepted (`manual ≥ ATR stop at T1`) is silently rejected here (`manual < ratchet floor at T2`). The code comment "IDENTICAL to build_portfolio_df" is inaccurate.

**Fix options:** Either (a) call `protective_stop` with the synthesis-frozen `_r["current_price"]` captured _before_ the live merge, or (b) accept the inherent skew (same accepted pattern as the breach gate) and remove the "IDENTICAL" comment. Option (b) is lower risk; option (a) requires capturing the pre-merge price in the loop.

### F3 — "Stop Unavailable" fallback fires Analysis breach banner the Brief skips (`app.py` ~12060) · **CONFIRMED MED**

**The problem:** When `_sa_holding["Stop"]` is `None` (the "Stop Unavailable" case — `build_portfolio_df` writes `stop = None` and `Gap to Stop (%) = None` when no ATR data exists), `_f(None)` returns `0.0` (falsy). The `or` fallback sets `_sa_stop = r.get("stop")` — the raw ATR bundle float, which may be valid. The Brief skips these rows explicitly:

```python
# daily_briefing.py
gap = _f(row.get("Gap to Stop (%)"), None)
if gap is None:
    continue   # ← ticker never evaluated for breach
```

Analysis has no equivalent skip. If the bundle has an ATR stop, the breach test fires and the `⛔` banner appears — contradicting the Brief's silence on the same ticker.

**Fix:** Mirror the Brief's skip. Before the breach test, check:

```python
if _sa_holding and _sa_holding.get("Gap to Stop (%)") is None:
    _stop_breached = False
else:
    _stop_breached = bool(
        _sa_holding and price and _sa_stop
        and round((price - _sa_stop) / price * 100, 1) <= 0
    )
```

### F4 — Ratchet tier labels garble breach-banner text (`app.py` ~12093) · **CONFIRMED LOW**

**The problem:** `_br_stoptype` is intended to produce a clean label for the banner ("ATR stop", "Manual stop", "Breakeven guard stop"). The code applies `removesuffix(" Stop")` expecting to strip a trailing " Stop" suffix, but all four ratchet tier labels from `_RATCHET_LEVELS` are:

```python
"Protect 40% gain", "Protect 25% gain", "Protect 10% gain", "Breakeven guard"
```

None ends with `" Stop"`. `removesuffix` is a no-op. The breach banner renders the raw internal string verbatim: "price is at/below your **Protect 10% gain** stop $X.XX".

**Fix:** Handle ratchet labels explicitly:

```python
_br_st = str(_sa_holding.get("Stop Type", "") or "").strip()
if not _br_st or _br_st == "Stop Unavailable":
    _br_stoptype = "ATR"
elif _br_st == "ATR Stop":
    _br_stoptype = "ATR"
elif _br_st == "Manual":
    _br_stoptype = _br_st
else:
    _br_stoptype = _br_st   # ratchet tier: use as-is but banner template must handle it
```

Or adjust the banner template to read naturally with tier labels ("price is at/below your **{_br_stoptype}** — stop $X.XX").

### F5 — `round(..., 1) <= 0` fires breach banner up to 0.049% above stop (`app.py` ~12071) · **PLAUSIBLE LOW**

**The problem:** The new breach test rounds the gap to 1 decimal place before comparing to zero. A price 0.049% above the stop rounds to 0.0% and fires the `⛔` banner even though the stop has not been breached. Example: stop=$50.00, price=$50.02 → gap = +0.04% → rounds to 0.0 → `_stop_breached = True`. The old `price <= _sa_stop` test would not fire.

This is intentional (to match the Brief's own rounding behavior), so both surfaces agree — but both share the false positive. Worth noting for a future Brief precision review. Not a correctness regression relative to the stated goal of mirroring the Brief.

### F6 — `_ac_map` uses `holdings_df` while all other Analysis rendering uses `_port_df_enriched` (`app.py` ~11428) · **PLAUSIBLE LOW**

**The problem:** `_ac_map` is built from `st.session_state.get("holdings_df")["Avg Cost ($)"]`. All other Analysis rendering reads avg cost from `_port_df_enriched` (the enriched portfolio built by `build_portfolio_df`). These are loaded from different DB queries (`db.load_holdings()` vs the full synthesis path) and can diverge after a trade is recorded mid-session — `recalculate_from_trades` updates `_port_df_enriched` but `holdings_df` may not have been refreshed. A wrong avg cost produces a wrong ratchet floor, causing the manual-stop gate to accept/reject differently from `build_portfolio_df`.

**Fix:** Read avg cost from `_port_df_enriched` instead:

```python
_sc_port = st.session_state.get("_port_df_enriched", pd.DataFrame())
_ac_map = (
    dict(zip(_sc_port["Ticker"].str.upper(), _sc_port["Avg Cost"]))
    if not _sc_port.empty else {}
)
```

### F7 — Manual-stop gate policy duplicated in `app.py` (CLAUDE.md violation) (`app.py` ~11457) · **PLAUSIBLE LOW**

**The problem:** CLAUDE.md states: *"Pure logic lives in `stock_analyzer/`; UI rendering and orchestration in `app.py`. Don't move domain logic into `app.py`."* The `_ms_p >= _prot` gate encodes the accept/reject policy for manual stop overrides. The identical policy lives in `build_portfolio_df` (`portfolio.py` ~line 299). Both must stay in sync — if `portfolio.py` tightens `>=` to `>`, `app.py` silently stays at `>=` and the divergence this commit closed reopens.

**Fix:** Extract a `apply_manual_stop(result_dict, manual_stop_price, avg_cost)` helper in `stock_analyzer/portfolio.py` and call it from both sites.

### F8 — `round(..., 1)` hardcoded in both `app.py` and `portfolio.py` (`app.py` ~12071) · **PLAUSIBLE LOW**

**The problem:** CLAUDE.md: *"Never hardcode decision thresholds. Every gate / threshold / boundary value lives in `stock_analyzer/constants.py`."* The rounding precision `1` in `round((price - stop) / price * 100, 1) <= 0` appears in both `app.py` (~12071) and `portfolio.py` (gap computation). If one is updated without the other, Analysis and the Brief use different precision and the breach test can fire at slightly different prices — re-opening the surface disagreement this commit closed.

**Fix:** Add `GAP_TO_STOP_ROUND_DECIMALS = 1` to `stock_analyzer/constants.py` and import it in both files.
