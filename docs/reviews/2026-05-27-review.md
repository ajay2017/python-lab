# Independent Code Review — DRISHTA · Beyond Noise

**Date:** 2026-05-27
**Scope:** Full codebase (`app.py` + all 38 modules in `stock_analyzer/`, ~27K lines).
**Method:** Independent read with no assumption that the original author's intent was correct. Findings cite specific file:line locations. Facts and opinions are labelled where the distinction matters.

---

## 1. Executive summary

This is a single-user, single-script (Streamlit) portfolio app backed by Supabase, with reasonable modular splits under `stock_analyzer/`. The domain math is mostly competent and there is genuine architectural discipline in places (constants module, signal-reconciliation authority, recommendations log, api_health instrumentation). However, the codebase has accumulated significant **operating risk**:

- **No tests at all.** A grep for `test_*` / `tests/` returns hits only in production modules. For an app whose entire purpose is to give the user *actionable* SELL/BUY calls, this is the single biggest concern.
- **Data-loss footgun** in `db.save_holdings` / `db.save_watchlist` — delete-then-insert with no transaction. A failure between the two wipes the table.
- **CLAUDE.md hard-rule #1 ("never hardcode thresholds") is violated in 13 of 17 advisor modules** — direct duplication of values that already exist in `constants.py`.
- **`None`-coerced-to-`0.0`** via `_f(val, default=0.0)` causes confident wrong-data displays in `risk_advisor`, `tax_advisor`, `stress_test`, `perf_advisor`, `evening_debrief`, and `trade_analytics`.
- Several **XSS vectors** in `app.py` from interpolating untrusted news headline titles/URLs into `unsafe_allow_html=True` markdown.
- **`stress_test.run_scenario` silently ignores `custom_spy_move`** for any sector in the override map — the "Custom SPY shock" UI is broken for most positions.

**Top 5 risks:**
1. `db.save_holdings` non-atomic wipe (C-1)
2. Risk Advisor / Tax Advisor / Stress Test false-positives on missing metrics (C-2, H-10)
3. `stress_test` ignoring custom SPY shock (C-6)
4. Tax-lot accounting error in `tax_advisor._earliest_buy` (C-7)
5. Absence of tests on financial-math code that decides what the user trades

**Recommended next action:** add a smoke test harness for `db.recalculate_from_trades`, `risk_advisor.build_risk_advisor_recommendations`, `portfolio.build_portfolio_df`, `scoring.combined_score`, `tax_advisor.build_tax_analysis`, `stress_test.run_scenario`, and a CSRF/XSS pass on every `unsafe_allow_html=True` in `app.py`. Wrap `save_holdings` / `save_watchlist` in a true upsert.

### C-1. `db.save_holdings` is a delete-then-insert with no transaction
[stock_analyzer/db.py:171-182](../../stock_analyzer/db.py)
The flow is `delete(...).execute()` then `insert(records).execute()`. There is no transaction, and the Supabase Python client doesn't expose one for the REST PostgREST path. If the insert fails (network blip, RLS misconfig, malformed row), every holding is gone — the recovery story is "rebuild from trades," which depends on the trade journal being complete. Same pattern in `save_watchlist` [stock_analyzer/db.py:526-540](../../stock_analyzer/db.py).
**Fix:** use an upsert on a unique key (add `unique(ticker)` constraint on `holdings`) — `client.table("holdings").upsert(records, on_conflict="ticker").execute()`. Then sweep tickers no longer in the DataFrame in a separate idempotent delete. If a true atomic replace is required, do it via a SECURITY DEFINER Postgres function called over RPC.

### C-2. Risk Advisor fires HIGH-priority recommendations on missing data
[stock_analyzer/risk_advisor.py:73-77, 223-224](../../stock_analyzer/risk_advisor.py)
`_f(port_risk.get("sharpe"))` returns `0.0` when Sharpe is `None`. Line 223 then triggers `if sharpe < 0.8` and labels priority `HIGH` for any portfolio where Sharpe could not be computed (cold cache, <10 days of history, missing SPY data). Same pattern for `var_pct`, `cvar_pct`, `max_dd`. The user sees a confident "**Sharpe 0.00 — Risk Taken Is Not Being Rewarded**" panel against a portfolio that just has no data.
**Fix:** use `_beta_ok`-style `None`-preserving coercion for every metric; gate each panel on `value is not None`.

### C-3. XSS / `javascript:` URL injection via news headlines
[app.py:583-586, 2415-2420, 3645-3650, 3683-3688](../../app.py)
News titles come from yfinance / RSS feeds (untrusted) and are formatted directly into `<a href='{url}'>{title}</a>` rendered with `unsafe_allow_html=True`. Title is escaped in some surfaces but not all; the URL is never validated for scheme. A hostile title like `</a><script>...</script>` or a `javascript:alert(1)` URL would execute in the user's browser session — which has access to Supabase-side-effecting buttons.
**Fix:** create a single `_safe_link(url, title)` helper that `html.escape`s the title and rejects any URL whose lowercased prefix isn't `http://` or `https://`. Use it everywhere news is rendered.

### C-4. Hardcoded composite-Buy threshold bypasses constants
[stock_analyzer/daily_briefing.py:877](../../stock_analyzer/daily_briefing.py) — literal `65` for buy-candidate gate.
[stock_analyzer/macro_playbook.py:284-290, 310, 320, 400, 549-556](../../stock_analyzer/macro_playbook.py) — eight policy thresholds hardcoded.
[stock_analyzer/signal_reconciliation.py:92,95](../../stock_analyzer/signal_reconciliation.py) — `-0.15` and `65` hardcoded.
These directly contradict CLAUDE.md hard-rule #1, and `macro_playbook.py:284`'s `_PROTECT_WEIGHT = 18.0` actually contradicts `SINGLE_NAME_CEILING = 15.0` in `constants.py` — the playbook tolerates more concentration than the rest of the app.
**Fix:** import from `constants.py`; reconcile `_PROTECT_WEIGHT` with `SINGLE_NAME_CEILING`.

### C-5. Module-level `_TODAY_ET` goes stale on long-lived sessions
[app.py:11](../../app.py) computes `_TODAY_ET = datetime.now(...).date()` **once at import**, then it is referenced 47 times. Streamlit Cloud workers can live across days; after midnight ET the value remains yesterday's date until the worker restarts. Every cache key, every "first-seen-today" check, every same-day rec match silently uses yesterday's date.
**Fix:** `def _today_et(): return datetime.now(_ET).date()` and call it on each rerun (the result is cheap to compute and the call sites already pass through it).

### C-6. `stress_test.run_scenario` discards `custom_spy_move` for mapped sectors
[stock_analyzer/stress_test.py:161, 179-198](../../stock_analyzer/stress_test.py)
`spy_move = custom_spy_move if custom_spy_move is not None else scenario["spy_move"]` — fine. But at line 179: `if sector in sector_map: est_move = sector_map[sector]` — and `spy_move` is never used in that branch. For every sector listed in the scenario's `_SECTOR_SHOCKS` table (which covers all the tech, healthcare, energy, financials sectors — i.e. almost the entire portfolio), the user-supplied custom SPY shock has zero effect. The UI shows "Custom shock: −15%" and silently runs the canned numbers from the 2022/COVID table.
**Fix:** `est_move = sector_map[sector] * (spy_move / scenario["spy_move"])` to proportionally scale historical sector moves with the custom shock, or hide the "Custom SPY" control when a sector_key is set.

### C-7. `tax_advisor._earliest_buy` mis-classifies multi-lot positions
[stock_analyzer/tax_advisor.py:32-45, 87, 93](../../stock_analyzer/tax_advisor.py)
The function returns `dates.min().date()` across **every** BUY for a ticker. If the user opened a position 2 years ago and added more shares 3 months ago, the entire current position is classified `LTCG` once the oldest lot matures — but the recently-added shares are still short-term. Downstream `tax_today` / `tax_savings` / `WAIT` / `HOLD_FOR_LTCG` actions are wrong for any position with multiple lots.
**Fix:** track per-lot holding periods; surface `gain_type = "mixed"` with a breakdown, or apply LTCG rate only to the share fraction that's truly LTCG-aged.

## 3. High-priority issues

### H-1. `data.py` price-fetch fallback silently returns the wrong ticker
[stock_analyzer/data.py:146,189](../../stock_analyzer/data.py): `col = close[ticker] if ticker in close.columns else close.iloc[:, 0]`. If a requested ticker is missing from yfinance's bulk download, this returns the **first ticker's** prices and writes them under the wrong key. A NVDA quote can end up labelled INTC. Same anti-pattern at [trade_review.py:102, 126](../../stock_analyzer/trade_review.py).
**Fix:** `if ticker not in close.columns: continue` and `_ah.record(..., "empty")`.

### H-2. Holdings/portfolio total-value division-by-zero
[stock_analyzer/portfolio.py:121-122](../../stock_analyzer/portfolio.py): `df["Weight (%)"] = (df["Market Value"] / total_val * 100)` — no guard. If every row has `Market Value == 0` (cold cache, all yfinance calls failed), `total_val = 0` → `inf`/`NaN` propagates into every downstream gate (rebalancer, risk_advisor, brief).
**Fix:** `total_val = df["Market Value"].sum() or 1.0` with a banner when zero.

### H-3. `_retry` blocks Streamlit for up to 18 s synchronously
[stock_analyzer/data.py:11-24](../../stock_analyzer/data.py): linear backoff of `3 × attempt`, three attempts → 18 s. No timeout on the inner `yf.Ticker().history(...)` call either. On a flaky network, the page hangs.
**Fix:** lower base backoff, add `requests`-level timeout (yfinance allows `timeout=` arg via session), and report partial degradation via `api_health.record(..., "rate_limit")` rather than blocking.

### H-4. N+1 yfinance loops across pages
app.py:959-963 (Home), 8444-8448 (Analysis), 9538-9542 (Watchlist), 2295-2299, 7828-7832. `load_all(t)` is called in a Python `for` loop per ticker. Even with the 1800 s cache, the cold-cache cost on deploy is N serial round-trips.
**Fix:** `concurrent.futures.ThreadPoolExecutor(max_workers=4)` around `load_all`, or batch in `stock_analyzer.data`.

### H-5. `recalculate_from_trades` silently tolerates over-sell
[stock_analyzer/db.py:392-394](../../stock_analyzer/db.py): `h["shares"] -= shares` then `if h["shares"] <= 1e-6: del`. A SELL larger than the current position drives shares negative; the negative passes the `<= 1e-6` check and the position is deleted silently. The user gets no warning that the trade history is internally inconsistent.
**Fix:** detect `h["shares"] - shares < -1e-6`, append to `warnings`, clamp at 0.

### H-6. Multiselect without explicit `key` (known landmine per memory)
[app.py:8338](../../app.py) — `st.multiselect("Add to Analysis Watchlist", options=candidates, default=…)` has no `key=`, and `candidates` varies by scanner filters. The memory file `feedback_streamlit_widget_options_state.md` documents that this pattern silently drops click events.
**Fix:** `key="_sc_add_to_wl"`.

### H-7. Holdings table has no unique constraint on `ticker`
Schema in [db.py:37-44](../../stock_analyzer/db.py) creates `holdings` without `unique(ticker)`. `save_holdings` (which UI assumes is "one row per ticker") doesn't deduplicate before insert. A bug or race that double-inserts a ticker silently breaks every consumer that does `set(df["Ticker"])` / weight math / split detection.
**Fix:** `alter table holdings add constraint holdings_ticker_unique unique(ticker);` and dedupe in `save_holdings`.

### H-8. Bare `except Exception: pass` swallowing all failures
Pervasive in `app.py` (app.py:1094, 1188, 1206, 1215, 1275, 4089, 4307, 4969, 6678, 6800), and in `macro_calendar.py:778-921` (six in `detect_macro_regime` alone). Auth errors, RLS denials, malformed FRED payloads, attribute errors — all silently absorbed. CLAUDE.md's own coordination rule says "set cache to `None` and render a visible banner" — these blocks violate that. Confirmed in 8 more modules in follow-up pass: `sentiment_velocity`, `news_intelligence`, `quick_research`, `trade_analytics`, `decision_journal`, `premarket_stance`, `comparison`, `evening_debrief`.
**Fix:** at minimum `_ah.record(...)` every swallow.

### H-9. No tests anywhere
No `tests/` directory; the only files matching `test_` are decision-journal pattern logic in source. The most safety-critical functions — `db.recalculate_from_trades`, `risk_advisor.build_risk_advisor_recommendations`, `portfolio.build_portfolio_df`, `scoring.combined_score`, `signal_reconciliation.reconcile_signals`, `trades.compute_realized_pnl`, `tax_advisor.build_tax_analysis`, `stress_test.run_scenario` — have no automated coverage.
**Fix:** add at least a `tests/test_finance_math.py` with golden inputs for these eight functions and run via `pytest` in CI.

### H-10. None-→-0.0 bug repeats across five more modules
Same shape as C-2: `_f(...)` defaults to `0.0`, then the `0.0` flows into a numeric gate or a dollar aggregation as if it were real data.

- **`tax_advisor.py:80-83`** — `shares`, `avg_cost`, `price`, `pnl` all `_f(...)`-coerced. A row with `Shares = None` becomes `cost_total = 0` and `harvestable = 0` and is silently treated as fully-disposed.
- **`stress_test.py:165, 174`** — `portfolio_value = _f(...)`, `mval = _f(...)`. A missing market value contributes `0` P&L to the scenario, so a stress run on a degraded portfolio reports a falsely benign result.
- **`perf_advisor.py:54, 57`** — `weight` / `mval` `_f`-coerced. Missing weight → no opportunity-cost is reported for that position.
- **`evening_debrief.py:114, 128, 188-189`** — `_f(p.get("score"))` makes missing scores look like `0.0`, which sort to the top of "weakest skip" lists.
- **`trade_analytics.py:121-125`** — `wr=0.0`, `avg_w=0.0` used in `exp_d = wr/100 * avg_w + (1-wr/100)*avg_l`; an all-loser trigger group is indistinguishable from a no-data group.

**Fix:** standardise on `_f(val, default=None)` for any field that gates a decision; switch consumers to `if x is None: continue` semantics.

### H-11. Date math uses system-local `date.today()` instead of ET
[tax_advisor.py:69](../../stock_analyzer/tax_advisor.py), [earnings_advisor.py:325](../../stock_analyzer/earnings_advisor.py), [watchlist_advisor.py:48](../../stock_analyzer/watchlist_advisor.py), [evening_debrief.py:292](../../stock_analyzer/evening_debrief.py).
All four advisors default `today = _date.today()`. Streamlit Cloud runs UTC; user is in ET. Between 7 PM and midnight ET, `date.today()` is already tomorrow UTC, so `days_until_earnings`, `days_to_ltcg`, and "same-day rec match" windows are off by one for ~5 hours every evening. CLAUDE.md explicitly forbids this.
**Fix:** all four should default to a shared `_today_et()` helper (which is *already* duplicated in three other modules — see M-2).

### H-12. `stress_test`'s beta fallback applies SPY shock to "Other"-sector positions in sector-specific scenarios
[stock_analyzer/stress_test.py:184-198](../../stock_analyzer/stress_test.py)
`AI Trade Unwind` defines `spy_move = -10.0`. A position in sector `"Other"` (not in `_SECTOR_SHOCKS["AI Trade Unwind"]`) falls into the beta fallback and gets `pos_beta × −10`, even though the scenario is supposed to be sector-targeted. So a portfolio mostly in "Other" sectors gets a broad-market shock under a name that promises AI-only repricing.
**Fix:** for sector-targeted scenarios, set `est_move = 0` (or a small generic shock) for non-listed sectors instead of beta × spy_move.

### H-13. `perf_advisor` hardcodes `$50,000` placeholder portfolio value
[stock_analyzer/perf_advisor.py:138](../../stock_analyzer/perf_advisor.py)
`pv = portfolio_value if portfolio_value > 0 else 50_000.0`. If portfolio value is missing/zero, dollar-alpha numbers are computed against a fabricated $50k — and shown to the user with no indication. The same anti-pattern exists in risk_advisor.
**Fix:** return empty list and a banner "portfolio value unavailable."

[macro_calendar.py:22](../../stock_analyzer/macro_calendar.py), [macro_playbook.py:17](../../stock_analyzer/macro_playbook.py), [split_detector.py:28](../../stock_analyzer/split_detector.py), plus `app.py:11`. Should be one helper.

[portfolio.py:17-39 `TICKER_SECTORS`](../../stock_analyzer/portfolio.py), [portfolio.py:494-505 `_SECTOR_CANDIDATES`](../../stock_analyzer/portfolio.py), [scanner.py:5-18 `SECTOR_UNIVERSE`](../../stock_analyzer/scanner.py). ### M-4. Scanner score thresholds collide semantically with composite
[scanner.py:95-104](../../stock_analyzer/scanner.py) uses 80/65/45/30 for "Strong Buy/Buy/Hold/Weak" labels, **identical strings to** `scoring.recommendation()` for composite. Two different scores can both produce "Strong Buy" labels with different meanings.

Per CLAUDE.md, domain logic belongs in `stock_analyzer/`. Macro-regime classification, leading-sector computation, `_quick_score` duplication, recommendations-log save logic, `_fmt_first_seen` helper, all embedded in `app.py`. ### M-6. `_retry` records the "error" event after a terminal `rate_limit`
[stock_analyzer/data.py:18-24](../../stock_analyzer/data.py): on the last attempt for a rate-limit case, both `rate_limit` and `error` are recorded — `api_health` double-counts.

### M-7. `protective_stop` label is misleading on big winners
[stock_analyzer/portfolio.py:60-64](../../stock_analyzer/portfolio.py): a position at +100% gain that has an ATR stop above the 40% floor returns label `"ATR Stop"`, not `"Protect 40% gain"` — the label only reflects the ratchet floor in some branches. The user sees "ATR Stop" and may believe profit isn't protected.
**Fix:** label by realized ratchet tier regardless of which floor wins.

### M-8. `weighted_average_cost` basis throughout `recalculate_from_trades`
[db.py:355-364](../../stock_analyzer/db.py): on partial sells, cost basis is treated as one weighted-average bucket, not FIFO/LIFO lots. This is a *policy* choice but it diverges from US tax accounting. For a personal portfolio app, fine — but **call this out** in `docs/architecture.md` so the user doesn't expect tax-correct numbers.

### M-9. Recommendations-history outcome dollars mix real and notional
[stock_analyzer/recommendations_history.py:147,154,165](../../stock_analyzer/recommendations_history.py): for acted SELL, `outcome_dollars` is realized `$`; for acted BUY, MTM `$`; for missed, `pct/100 * 1000` (i.e., per-$1000 notional). Summing this field across recs (which the UI almost certainly does) returns a meaningless number.
**Fix:** two fields — `outcome_dollars_actual` and `outcome_dollars_per_1k`.

### M-10. Yahoo's news payload schema-divergence guarded only partially
[stock_analyzer/data.py:371-399](../../stock_analyzer/data.py): handles old and new yfinance news shapes. Good. But `_TIER1`/`_TIER2` (lines 309-317) are case-sensitive substring tests; flag for future audit.

### M-12. Sentiment-velocity recent/prior split is biased on odd N
[stock_analyzer/sentiment_velocity.py:95-97](../../stock_analyzer/sentiment_velocity.py)
`mid = len(articles) // 2`; `recent = articles[:mid]`; `prior = articles[mid:]`. For an odd N=5: recent has 2 items, prior has 3. The "prior" window has *more* samples than the "recent" window. Velocity = recent_mean − prior_mean is then noisier on the recent side.
**Fix:** `mid = (len(articles) + 1) // 2` so recent gets the extra article — matches the "newest half" docstring.

### M-13. `sentiment_velocity._parse_ts` silently drops items with unparseable timestamps
[stock_analyzer/sentiment_velocity.py:30-41, 66](../../stock_analyzer/sentiment_velocity.py)
Returns `ts = 0` on `fromisoformat` failure; line 66 filters out anything with `ts <= 0`. During a yfinance outage that strips `providerPublishTime`, velocity silently falls back to "no news" rather than "stale data unavailable."
**Fix:** for the `current_score` computation, keep items with ts=0; exclude only from the temporal recent/prior split.

### M-14. `tax_advisor` STCG → LTCG sells assume best-case waited-out execution
[stock_analyzer/tax_advisor.py:127-131](../../stock_analyzer/tax_advisor.py)
`tax_ltcg = tax_today − tax_savings` is computed assuming the user *can* and *will* wait every STCG position to LTCG. There's no opportunity-cost adjustment (a position rated Sell that has 200 days to LTCG probably can't be held) and no probability term. The `tax_savings` number shown in the UI is an upper bound, not an expectation.
**Fix:** document this in the function docstring and/or scale by probability the position survives to LTCG.

### M-15. `premarket_stance.parse_stance` substring match misfires on prose containing "stance:"
[stock_analyzer/premarket_stance.py:149-150](../../stock_analyzer/premarket_stance.py)
`if "Stance:" in ln or "stance:" in ln:` — a narrative sentence like *"The market shifted to a defensive stance: equities sold off…"* would match and that line would be parsed as the verdict (defaulting to "Neutral" because no Defensive/Neutral/Constructive keyword follows in the expected position). The verdict line then gets stripped from the narrative.
**Fix:** anchor regex `^\s*Stance\s*:\s*(Defensive|Neutral|Constructive)\b` to start-of-line.

### M-16. `comparison._portfolio_fit` computes unused `total_val`
[stock_analyzer/comparison.py:435](../../stock_analyzer/comparison.py)
`total_val = float(port_df.get("Market Value", [0]).sum() or 1)` — assigned, never used in the function (the subsequent code uses pre-computed `Weight (%)` columns). Dead code.
**Fix:** delete the line.

### M-17. `targets.py` momentum projection uses linear-not-compounded drift (minor)
[stock_analyzer/targets.py:53-54](../../stock_analyzer/targets.py)
`momentum_target = current_price * (1 + monthly_drift * 3)` — should be `(1 + monthly_drift) ** 3` for 3-month compounding. For typical drifts (~2%/month) the error is ~0.1%; not material but visibly wrong to anyone who knows the formula.
**Fix:** `**3` instead of `*3`.

### M-18. `targets.py` fallback floors and bear-case factors are unnamed magic numbers
[stock_analyzer/targets.py:35,36,44,45,48,67,68,77,78](../../stock_analyzer/targets.py): `0.25`, `0.10`, `1.3`, `0.7`, `0.88`, `1.12`, `1.25`, `6.0`, `0.98`, `1.03`. Each is a documented investment heuristic; collectively, they're invisible to the constants-file maintainer.
**Fix:** named constants in `targets.py` at minimum.

### M-19. `news_intelligence` uses ticker symbol as sector fallback
[stock_analyzer/news_intelligence.py:81](../../stock_analyzer/news_intelligence.py)
`"sector": pos.get("sector", ticker)` — when a ticker isn't held, the ticker symbol fills in for sector, polluting per-sector aggregates with single-ticker pseudo-sectors. Benign but confusing in the sector digest.
**Fix:** default to `""` and skip in sector_digest aggregation.

### M-20. `trade_analytics` hold-time pairing isn't FIFO-lot-aware
[stock_analyzer/trade_analytics.py:81-99](../../stock_analyzer/trade_analytics.py)
Pairs each SELL with the *nearest preceding BUY*, not actual FIFO lots. A 3-BUY → 1-SELL position has its hold time computed against the most-recent BUY only, understating the average hold time.
**Fix:** at minimum document; ideally weight across all BUYs ≤ sell date.

### M-21. `decision_journal` accuracy insight has no minimum sample size
[stock_analyzer/decision_journal.py:122,129](../../stock_analyzer/decision_journal.py)
`if len(costly_list) >= 2:` is the only minimum-sample guard. The `f_acc` / `i_acc` accuracy comparison at line 129 has none — a 1-trade override that happened to be a win would print as "Your overrides are outperforming signals (100% vs 50%)" with full confidence.
**Fix:** require `f_wins + f_losses >= 5` and similarly for ignored before printing the accuracy insight.

### M-22. `tax_advisor._STCG_THRESHOLD_DAYS = 366` — *correct* (noted to prevent future "fix")
IRS rule: "held more than 1 year" means an asset bought Jan 1 and sold Jan 1 next year is **365 days = not more than 1 year**; sold Jan 2 = **366 days = more than 1 year**. So `days_held >= 366` is correct. Noting for the record so a future maintainer doesn't "fix" it.

## 7. Systemic observations

1. **None vs zero conflation** is the single most common bug pattern. `_f(...)` defaulting to `0.0` is used everywhere (per M-1), and downstream code interprets `0.0` as a real datapoint — see C-2 (Risk Advisor), H-2 (portfolio weight), H-10 (5 more modules). When a value is *missing*, the code should branch to "data unavailable" UX, not feed `0.0` into a gate.
2. **Hardcoded thresholds keep escaping `constants.py`.** Confirmed in 13 of 17 advisor modules — this is no longer drift, it's the dominant style. The CLAUDE.md rule needs to be enforced by code review *plus* a lint script that greps for numeric literals in advisor files.
3. **Bare `except` is endemic.** Confirmed in app.py + 9 modules. It hides the very failures the user needs to see. Set a project rule: every `except` either re-raises, records to `api_health`, or sets a session_state cache to `None` so the consumer can render the "unavailable" banner CLAUDE.md requires.
4. **No tests anywhere on financial math.** The math is mostly correct *today*, but every advisor rewrite risks regressions in numbers the user is going to act on with real money. This is the single biggest deferred risk.
5. **`app.py` has grown organically.** It does navigation, page rendering, advisor orchestration, recommendation logging, and partial domain logic. Splitting it page-by-page would isolate regressions and let agents work in scope.
6. **Three sector taxonomies, multiple `_f` definitions, multiple `_today_et()` copies.** Helpers/data without a clear home accumulate as duplicates. A `stock_analyzer/_util.py` and a `stock_analyzer/sectors.py` would absorb them.
