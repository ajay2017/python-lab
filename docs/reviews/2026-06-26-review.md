## 1. Executive Summary

The codebase is in good structural health: secrets hygiene is clean, RLS is correctly enforced, the read-only viewer guard is complete at the db.py chokepoint, no SQL injection vectors exist, and the core recommendation/gate decision path is sound (no double-surface, no broken gate, no threshold contradiction). The project's core conventions — `_pending_page` indirection, def-before-use ordering, `None` vs empty-container for offline signaling — are followed consistently.

**Three areas need attention before the next incident:**

1. **The premarket alert dedup is broken** — a changed protective alert on the second DST-straddle slot can be silently swallowed. On the highest-stakes surface ("reach me now"), the dedup logic doesn't match the fix already applied to the buy lane.
2. **A DB read error on `load_watchlist` injects a hardcoded phantom watchlist** — transient Supabase unavailability silently swaps in NVDA/AMD/INTC/MU, which can trigger spurious picks and alerts for names the user doesn't track.
3. **`COMPOSITE_SELL` (30) is hardcoded inline** in `portfolio.py`, violating the project's own hard rule that all gate boundaries live in `constants.py`.

Recommended next action: fix the three critical items in sequence (cron dedup first — it's live and active), then address the high-priority earnings timezone bug, then schedule the medium items.

## 2. Critical Issues

### C1 — `cron_runner.py:99-104` — Premarket dedup date-flag fires before fingerprint check; changed alert set on 2nd slot silently dropped

> **✅ FIXED `150bc15`** — Removed the date-only early-return from `_run_premarket`. The DST second slot now always recomputes; fingerprint check at line 119 handles dedup. Open Question 3 answered: both slots independently evaluate.

The `_run_premarket` function saves `last_emailed_date = today_str` on *every* run (line 125), even when no alerts were found or nothing was sent. The first DST-straddle slot (e.g. 12:00 UTC) computes an empty or unchanged set, writes today's date, and returns. The second slot (13:00 UTC) then hits the `last_emailed_date == today_str` guard at line 99 and short-circuits *before* recomputing — so a genuinely new protective signal that materialized between the two slots is never emailed that day.

**Why it matters:** this is the highest-priority surface ("reach me before market open"). The DST straddle exists as a safety net, and this bug defeats it.

The buy lane already has the correct pattern (lines 261-273): gate on `date AND fingerprint`, save state only on a real send. The protective lane must match.

**Minimal fix:**
```python
# Remove lines 99-101 (the date-only early-return).
# Rely solely on the fingerprint comparison at line 119 for dedup.
# Move the last_emailed_date persist inside the `if sent:` block at ~line 125.
```

### C2 — `cron_runner.py:125` — Protective state persisted even when Resend send failed

> **✅ FIXED `150bc15`** — `save_alert_state` now gated on `sent or not alerts`. A transient Resend failure no longer writes the fingerprint, so the later DST slot retries.

`save_alert_state` is called unconditionally after compute, regardless of whether the email was actually sent. On a transient Resend failure, the fingerprint is written; the second slot then sees the same fp and suppresses the retry.

**Why it matters:** the buy lane explicitly fixed this exact bug with the comment "Save dedup state ONLY on a real send … so a transient Resend failure … is retried." The protective lane — the only one that matters at 08:00 ET — doesn't have this protection.

**Minimal fix:**
```python
# Gate save_alert_state on `sent or not alerts` (legitimately nothing to send),
# not unconditionally.
if sent or not alerts:
    db.save_alert_state(...)
```

### C3 — `stock_analyzer/db.py:617-619` — `load_watchlist` returns hardcoded default on DB read error, silently injecting phantom picks

> **✅ FIXED `150bc15`** — `load_watchlist` now returns `[]` on DB exception. `_DEFAULT_WATCHLIST` kept only for the explicit no-DB-configured path. Open Question 1 answered: treated as first-run seed only.
>
> **⚠️ SUPERSEDED IN PRACTICE 2026-08-17 (F-243).** The decision above still stands as written, but its only surface is gone: `app.py`'s startup load now calls `db.load_watchlist_or_none()`, which returns **`None`** when there are no credentials, and the app renders `[]` rather than the seed. So a no-DB first run no longer produces NVDA/AMD/INTC/MU. `load_watchlist()` and `_DEFAULT_WATCHLIST` are retained deliberately — deleting them would silently reverse this recorded decision — but they now have **zero production callers** and are pinned by a test as a *trap*: the next person who autocompletes to `load_watchlist()` reintroduces exactly this C3 defect. Reason for the change: on a DB-backed production deploy, "no DB configured" means an OUTAGE, not a fresh install, so seeding a watchlist the user never created presents invented data as theirs.

On any `except Exception`, `load_watchlist` returns `_DEFAULT_WATCHLIST` (NVDA/AMD/INTC/MU) — the same list used for the "no DB configured" path. A transient Supabase read failure is treated identically to a fresh install, so those four names enter the tracking universe and can generate spurious scanner hits, alerts, and catalyst watch entries.

Compare: `load_holdings` and `load_trades` both return `[]` on error. `load_watchlist` should do the same.

**Minimal fix:**
```python
except Exception as e:
    st.warning("Could not load watchlist — using empty list until restored.")
    return []   # was: return _DEFAULT_WATCHLIST
# Keep _DEFAULT_WATCHLIST only for the explicit no-DB-configured path.
```

### H2 — `app.py:7284, 10415, 11006, 11122` — `date.today()` (UTC) in earnings-proximity decision gates instead of `_today_et()`

> **✅ FIXED `150bc15`** — All 4 sites replaced with `_today_et()`.

Streamlit Cloud runs UTC. Between 19:00–00:00 ET (00:00–05:00 UTC), `date.today()` is already tomorrow while ET is still today. `days_to_earn` is under-counted by 1, which can flip a 14-day, 21-day, or 30-day gate boundary and drop or trigger an earnings warning at the wrong time.

`_today_et()` exists at `app.py:16` for exactly this. All four sites use the raw `date.today()` call.

**Fix at each of the four lines:** replace `date.today()` with `_today_et()`.

## 6. Patterns Worth Keeping

- **Read-only viewer guard at the db.py chokepoint.** Enforced behind all 14 write paths, not as a UI concern. New writers correctly inherit it.
- **`None` = offline signaling convention.** Gate caches set to `None` (not `[]`/`{}`) when a producer fails, allowing downstream consumers to detect "unavailable" and show banners rather than silently disabling.
- **`_pending_page` indirection for navigation.** The `StreamlitAPIException` trap is real; the indirection pattern is implemented correctly and hasn't leaked.
- **`_safe()` API-key redaction in FMP provider.** Every error path through `http_get_json` is wrapped before hitting `api_health.record`. The pattern is consistent across the provider layer.
- **NaN-Close strip invariant across all three data paths.** `compute_indicators`, `load_bundle_cache`, and `bundle_loader` all independently guard it, so the invariant holds regardless of data entry point.
- **Buy-lane dedup correctness.** `_run_scan` gates on `date AND fingerprint` and saves state only on a real send — which is exactly why the protective lane's divergence (C1/C2) stands out.
- **Fundamentals withhold gate.** Verdict withheld (not neutral-50) when all sources fail, preventing Brief↔Analysis contradictions.

## 7. Systemic Observations

**Falsy-numeric `or` is the recurring data-quality trap.** `targets.py:46`, `exit_advisor.py:277`, `risk.py:8`, and `db.py:617` all share the pattern `value or fallback` on numeric/container fields. The correct idiom is `if value is None`. This pattern should be audited across all provider-data consumers.

**The protective cron lane didn't get the buy-lane's dedup fixes.** C1 and C2 are both divergences from a pattern the buy lane already fixed. When the dedup logic was hardened for the buy lane, the protective lane was not updated in parallel. Any future logic change to one send path should prompt an immediate review of the other.

**Policy-flavored literals appear in scoring modules despite the constants.py rule.** Sub-score band cutoffs in `fundamentals.py` affect scores which affect gates. The line between "scoring internals" and "policy literals" is blurry. Pragmatic rule: anything that appears as a named tier in a comment or docstring should be a named constant or dict — making it greppable is the minimum bar.

**Two runtimes share db.py but have different secret-loading paths.** The env-first / `st.secrets`-fallback in `_supabase_creds` handles this correctly today. If a third runtime is added, the precedence logic should be documented explicitly.
