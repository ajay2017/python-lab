# DRISHTA — UX Audit
*2026-07-13 · Full app · app.py (20,983 lines) + stock_analyzer/ advisor modules*
*Remediation completed 2026-07-14 · All findings resolved — see status on each item below*

---

## Executive Summary

DRISHTA is a well-designed decision-support tool with strong data transparency and a clear "decides, not informs" posture throughout. The most significant UX debt is **terminology inconsistency** — the same concept (composite score, signal, alert) is labelled differently across pages, forcing users to mentally re-map vocabulary as they navigate. The single biggest opportunity is a targeted consistency pass across the five core vocabulary axes (score, signal, urgency, action, alert), which would materially reduce cognitive friction on every daily session without touching any decision logic.

## Critical Issues (fix before launch)

### C1 — Duplicate 📊 icon in sidebar navigation
- **Location**: `app.py` lines 1391–1475 (sidebar nav); the two entries are `"📊 Portfolio Allocation"` (PORTFOLIO group) and `"📊 Predictive Analytics"` (also PORTFOLIO group), and the Predictive Analytics page title `st.title("📊 Predictive Analytics")` also collides with the tab-level heading `"📊 Alpha Attribution"` on that same page (line 18429)
- **Problem**: Three separate UI surfaces use 📊 simultaneously. Users who use icon recognition to navigate quickly (common on a dense dashboard used daily) cannot distinguish Portfolio Allocation from Predictive Analytics at a glance. Severity: medium-high — both pages live in the same PORTFOLIO group, so they appear adjacent.
- **Recommendation**: Assign `"📊 Portfolio Allocation"` a distinct icon — `"🥧"` (pie chart) or `"⚖️"` — and rename `"📊 Alpha Attribution"` inside the Predictive Analytics tab to `"🔬 Alpha Attribution"` to eliminate the triple collision.
- **Status**: ✅ FIXED — commit `0b7417c` (pass 1). Portfolio Allocation icon changed to 🥧 throughout (nav, dispatch, internal tab, User Guide). Alpha Attribution removed from `st.tabs()` entirely and placed in a collapsed `st.expander` below the 4 live tabs (C4). Predictive Analytics moved to RESEARCH group (I5) so the two 📊 pages no longer sit adjacent.

### C2 — Internal module path visible in user-facing copy
- **Location**: `app.py` line 8312, Rate Sensitivity table caption on the 🔗 Risk Analysis page
- **Problem**: The caption reads *"Sector Score is the `macro.RATE_SENSITIVITY` structural label"*. `macro.RATE_SENSITIVITY` is a Python attribute reference from `stock_analyzer/macro.py` — a developer identifier, not a user-facing term. A retail investor reading this does not know what a "macro module" is.
- **Recommendation**: Replace with *"Sector Score is a structural sensitivity label (−1.0 = most rate-sensitive, +1.0 = rate-resilient)"*. The range values already appear in the preceding sentence and carry the meaning; the module path adds nothing.
- **Status**: ✅ FIXED — commit `0b7417c` (pass 1). Caption now reads *"Sector Score is a structural sensitivity label"*; the module reference is removed.

### C3 — "BQ" abbreviation appears without expansion in a primary decision surface
- **Location**: `app.py` line 12503–12507, the verdict formula on 📈 Analysis (repeated for every analysed ticker tab)
- **Problem**: The formula `Technical 25% + BQ 35% + Val 30% + Sentiment 10%` renders with HTML `<abbr>` tooltips on hover for "BQ" and "Val", but `abbr` hover is invisible on mobile and is not discoverable on desktop — users frequently don't hover over formula abbreviations. "BQ" (Business Quality) carries 35% of the total composite and is the most consequential pillar; misreading it as "book quality" or ignoring it is a real risk when the user is deciding whether to act on a Buy signal.
- **Recommendation**: Change `BQ` → `Business Quality` and `Val` → `Valuation` in the inline formula. The three-character savings are not worth the ambiguity. The `<abbr>` wrappers can stay as supplemental hover-help once the full names are visible.
- **Status**: ✅ FIXED — commit `0b7417c` (pass 1). Formula now reads `Technical 25% + Business Quality 35% + Valuation 30% + Sentiment 10%`.

### C4 — Live placeholder tab visible as a navigation target on Predictive Analytics
- **Location**: `app.py` lines 18424–18429 (`st.tabs([..., "📊 Alpha Attribution"])`), content at lines 18824–18865
- **Problem**: "📊 Alpha Attribution" is a fully visible tab in the 5-tab row. Clicking it shows an `st.info` card: *"Coming once you have 6+ months of daily portfolio snapshots"*. The tab appears equal-weight alongside four working tabs; a user who clicks it on a busy trading morning sees a dead end and must back-track. The page caption at line 18268 also mentions "(coming soon)" mid-sentence, making the feature boundary ambiguous before the user even selects a tab.
- **Recommendation**: Remove the tab from the `st.tabs()` call and add the progress meter and "coming soon" description inside a collapsed `st.expander("📊 Alpha Attribution — activates after 180 days of snapshots")` below the four live tabs. This keeps the feature visible without occupying a tab slot that currently delivers nothing.
- **Status**: ✅ FIXED — commit `0b7417c` (pass 1). Tab removed from `st.tabs()`; content moved to a collapsed `st.expander("📊 Alpha Attribution — activates after 180 days of snapshots")` below the 4 live tabs. Page is now a 4-tab layout.

## Improvements (high value, not blocking)

### I1 — Alerts & Actions page has four visually undifferentiated sections at very different urgency levels
- **Location**: `app.py` lines 7119–7858 (full page)
- **Problem**: The page presents four distinct conceptual sections in a flat vertical scroll with only `st.divider()` between them: (1) Active portfolio alerts (grouped by category — stop/signal/concentration/earnings/revisions), (2) Custom price alerts, (3) Rebalancing Recommendations (full evidence panels + decision checklists), (4) Diversification Advisor. A user arriving with a stop-loss alert active will scroll past it and into Custom Price Alerts before reaching the Rebalancing section. Sections 1 and 3 both say "act now" but at very different timescales — no visual grouping makes the distinction clear.
- **Recommendation**: Introduce section headings above each of the four blocks (using `st.subheader` with a severity color or badge) and move "Custom Price Alerts" to its own page tab or expander — it is a configuration surface, not an alert surface. Consider separating "Active Alerts" and "Rebalancing Recommendations" from the same page, or at minimum reordering: Rebalancing (same-day action) before Custom Price Alerts (setup/config).
- **Status**: ✅ FIXED (partial) — commit `5f2a62b` (pass 2). Custom Price Alerts config form wrapped in a collapsed `st.expander`; store initialisation and fired-alert trigger check moved outside the expander so they run unconditionally. Fired alerts render above the expander. Full section reordering (Rebalancing before Custom Alerts) was not done — the 400+ line block reorder was judged higher risk than the expander approach for the same UX outcome.

### I2 — "Momentum" vs "Composite" vs "Score" labelled differently on the same screen
- **Location**: `app.py` line 5100 (Grow Today cards, Today's Brief), line 12378 (`summary_df` column label on Analysis Scorecard), line 7295–7311 (Alerts & Actions score breakdown), line 8259 (Risk Analysis Diversification metric)
- **Problem**: The same number is displayed as: "Momentum 85/100" (Grow Today new picks), "Composite 72/100" (same card), "Score" (Analysis Scorecard column header), "Total score" (Risk Analysis), and implicitly in the "Decision Checklist" where it appears without a name label. Users who navigate from Today's Brief → Alerts & Actions → Analysis encounter three different labels for the same composite value, and must infer that "Score 72" on the Scorecard equals "Composite 72/100" on the Brief card.
- **Recommendation**: Standardize to "Composite Score" everywhere the 4-pillar aggregated number is shown. Reserve "Momentum" for the single-factor momentum-only reading (already correct in the formula breakdown `Momentum 85/100 · Composite 72/100`). Update the Analysis Scorecard column header from "Score" → "Composite" and the Risk Analysis metric from "Total score" → "Composite Score".
- **Status**: ✅ FIXED — commits `5f2a62b` / `76e61d5` (passes 2+3). Analysis Scorecard column: "Score" → "Composite Score". Add-to-winner cards: "Score N/100" → "Momentum N/100" (correct — that field is `port_df["Score"]`, the single-factor scanner score, not the 4-pillar composite). Lines 7295 ("Score Breakdown" section header) and 8259 ("Diversification Score" metric) were audited and confirmed as correctly named — "Score Breakdown" is a section heading, "Diversification Score" is a distinct metric unrelated to the composite.

### I3 — Bear-mode "Defer New Entries" empty state gives no exit condition
- **Location**: `app.py` lines 4824–4849 (`_render_grow_today`); bear_msg rendered at line 4847
- **Problem**: When the market tone is "bear", the Grow Today section shows the bear_msg (sourced from `daily_briefing._grow_today`, typically something like "Bear tape — holding off on new positions") and immediately returns (`return` at line 4849). The user sees a section header `"🛡️ Defer New Entries"` and a single caption line with no link to what changes the tone, how long bear mode typically lasts, or where to check tone-flip conditions.
- **Recommendation**: Add a line below the bear_msg: *"Tone flips to Neutral or Growth once SPY recovers above its trend line and volatility recedes — check today's tone status in the 🌐 Macro page."* This requires no code change to business logic, only supplemental copy in the empty-state branch.
- **Status**: ✅ FIXED — commit `5f2a62b` (pass 2). Caption added below bear_msg pointing to 🌐 Macro for tone-flip conditions.

### I4 — "Refresh macro" vs "Refresh Signals" button labels are ambiguous
- **Location**: `app.py` lines 3946–4093 (the 4-column status bar below Today's Brief header)
- **Problem**: The status bar has two separate refresh buttons: "🔄 Refresh macro" and "🔄 Refresh Signals". From the UI, it is not apparent what "macro" covers vs what "Signals" covers. A user who runs "Refresh Signals" and sees no change may have needed "Refresh macro" instead (or vice versa) and cannot make the right choice without memorizing the architecture distinction.
- **Recommendation**: Add `help=` tooltip text to both buttons distinguishing their scope: *"Refresh macro: updates VIX, SPY trend, cross-asset pulse, and market regime."* and *"Refresh Signals: re-scans the stock universe and recomputes composite scores for all picks."* This uses existing Streamlit capability and requires no layout change.
- **Status**: ✅ ALREADY ADDRESSED — both buttons already had `help=` tooltips when the code was inspected during the remediation pass. No change needed.

### I5 — "Predictive Analytics" placed in the PORTFOLIO nav group, not RESEARCH
- **Location**: `app.py` lines 1391–1475 (sidebar nav)
- **Problem**: Predictive Analytics is a historical performance calibration tool (how well the engine's signals have worked for you over time). Its content is entirely backward-looking (acted vs missed alpha, calibration curves, sector alpha) — it has no forward portfolio recommendations and does not require portfolio data to render. Placing it in the PORTFOLIO group alongside Trade Journal, Trade Review, and Risk Analysis suggests it is a portfolio-management action surface, which it is not.
- **Recommendation**: Move "📊 Predictive Analytics" from the PORTFOLIO group to the RESEARCH group (with Analysis, Compare, Watchlist, Macro). Its closest conceptual neighbours are the Analysis and Recommendations History pages.
- **Status**: ✅ FIXED — commit `0b7417c` (pass 1). Predictive Analytics moved from PORTFOLIO to RESEARCH nav group, positioned after 🌐 Macro.

### I6 — Analysis page: first visible content is a dense scorecard table, not a verdict summary
- **Location**: `app.py` lines 12303–12412 (Summary Scorecard rendered before Detailed Analysis)
- **Problem**: For a single-ticker analysis (the most common use case, triggered by "▶ Analyze TICKER" buttons), the first thing the user sees is a multi-column `st.dataframe` with 11 columns including "Position / Entry", "Stop", "Base Target", "R:R", "Shares", "P&L / Cost", "Earnings". This is a good reference surface but not the right first impression — the verdict and rationale (the answer to "should I act?") are below the scorecard, inside the per-ticker tabs.
- **Recommendation**: When exactly one ticker is being analyzed, render the verdict banner first (the colored `rec['label']` + `rec['rationale']` block at line 12495) then the detailed scorecard, reversing the current order. For multi-ticker analysis the table-first layout is appropriate as a comparison surface.
- **Status**: ✅ FIXED — commit `5f2a62b` (pass 2). For single-ticker analysis, a verdict banner (label + composite score + rationale) now renders above the Summary Scorecard. Multi-ticker analysis retains table-first layout.
