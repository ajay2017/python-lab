# DRISHTA — UX Audit
*2026-06-27 · Full app · All pages and stock_analyzer UI modules*

---

## Executive Summary

DRISHTA is a technically sophisticated app whose core UX challenge is **signal-to-noise ratio at the page level**: the Home page attempts to deliver 8–10 distinct advisory layers simultaneously, which buries the most actionable content under scroll. The single biggest opportunity is restructuring the Daily Brief so that protection actions (exits, stop breaches) appear before new-entry recommendations — matching how a responsible advisor actually sequences advice. Developer-facing model terminology ("composite", "cache", "SMA{N}") leaks into user-facing copy in roughly a dozen places and should be systematically replaced with plain language before any external user sees the app.

## Critical Issues (fix before launch)

### C1 — Daily Brief section order prioritizes growth over risk
- **Location**: Home (`app.py` — Daily Brief render, `daily_briefing.py`)
- **Problem**: Current order: Pre-Market Intel → **Grow Today** → **More Buy Candidates** → Protect Mode → Holdings Earnings → Macro → Advanced Risk Metrics. A user with an open stop-breach alert sees four buy opportunities before they see "SELL — Stop Breached." For an app whose posture is "decides, not informs," this ordering directly causes harm — a user who scrolls to the first actionable item and acts on a buy signal when they should be exiting.
- **Recommendation**: Reorder to: Pre-Market Intel → **Protect Mode / Act Today** → Holdings Earnings → Grow Today → More Buy Candidates → Macro → Advanced Risk Metrics. Protect always precedes deploy.

> **Resolved `f38e056` — swapped two-column assignment so Act Today renders left (first-seen) and Grow Today right**

### C2 — Developer jargon is user-facing throughout
- **Location**: Home (Daily Brief), Watchlist, Market Scanner, Analysis page
- **Problem**: Internal model concepts appear verbatim in UI copy. Specific instances:
  - `"❌ Conflicted — Composite vs Technical"` — user does not know what "Composite" or "Technical" means as distinct signals
  - `"🔍 Verify — Composite Signal Missing"` — user action is unclear; "Verify" with what?
  - `"Composite score {score}/100 is in the Sell zone"` — "composite" is not a word users reach for
  - `"Checking for unaccounted stock splits…"` — reads like a log line, not a UI spinner
  - `"📦 Showing last-known-good data"` — cache terminology; users don't think in terms of cache
  - `"Pending Verification — Refresh button"` — what is being verified? by whom?
- **Recommendation**: Audit every string containing "composite," "cache," "validator," "tier," "SMA[number]." Replace:
  - "Composite vs Technical" → "Signals disagree"
  - "Composite Signal Missing" → "Full score not yet calculated"
  - "Showing last-known-good data" → "Showing cached data from {date} — live prices unavailable"
  - "Pending Verification" → "Awaiting data — click Refresh"

> **Resolved `2f58caa` + `a31bfaa` — jargon cleanup across app.py (cached data, Score, independent source) and full sweep of signal_reconciliation.py (Signals Disagree, All Signals Agree, Score: {n}/100)**

### C3 — "Grow Today" and "More Buy Candidates" are indistinguishable to users
- **Location**: Home page, Daily Brief (`daily_briefing.py`)
- **Problem**: Two separate buy sections with no inline explanation of how they differ. The code distinguishes them (Grow Today = passes all 5 gates; More Buy Candidates = scanner picks without full composite gating), but this is invisible to the user. A user who acts on a "More Buy Candidate" may be entering a position that the app's own full analysis would reject.
- **Recommendation**: Either (a) add a one-line caption below each section heading explaining the distinction ("These passed all portfolio checks" vs. "Scanner picks — run Analysis before entering"), or (b) rename to make hierarchy explicit: "✅ Ready to Enter" and "🔍 Worth Investigating."

> **Resolved `f38e056` — added subtitle under Grow Today ("Cleared all 5 portfolio checks — vetted for entry") and sharpened More Buy Candidates caption ("not yet validated by the full portfolio check")**

### C4 — High-stakes actions have no confirmation step
- **Location**: Trade Journal (`app.py` — Trade Journal form), Home page action buttons
- **Problem**: "Sell all {shares} shares at next open — mechanical stop rule" is the highest-stakes recommendation the app makes. The Trade Journal form submits on button click with no confirm dialog. A fat-finger or misread ticker creates a false P&L record that distorts the Recommendations History audit trail.
- **Recommendation**: For SELLs only, add an inline read-back confirmation card after form fill: "You are recording: SELL 150 shares of NVDA at $132.50 on 2026-06-27. Confirm?" with green Confirm and gray Cancel. One extra click for high-stakes; zero extra clicks for browsing.

> **Resolved `7793be2` — SELL-only two-step confirmation card: validated record stashed to `_tj_pending_sell`, confirmation card shows ticker/shares/price/P&L, [✅ Confirm SELL] / [✗ Cancel]; BUY unaffected**

### C5 — MONITOR and HOLD_OFF_EARNINGS signals have no actionable follow-through
- **Location**: Home (Daily Brief Protect Mode), Watchlist page
- **Problem**: Several outputs instruct the user to act at a future time with no mechanism:
  - `"MONITOR — Critical News: A second negative headline OR price −3% intraday → exit"` — no alert or reminder
  - `"HOLD_OFF_EARNINGS — Wait for the earnings report. Then evaluate the post-earnings setup"` — user has no prompt to return after earnings
  - `"Be prepared to exit at market open if the report is negative"` — requires the user to remember to open the app
- **Recommendation**: For MONITOR signals: add a "📌 Set reminder" button (session_state flag; banner at next open). For HOLD_OFF_EARNINGS: add "Re-evaluate after {DATE}" badge on the watchlist item using existing chip patterns.

> **Resolved `fca045a` — re-evaluate date surfaced inline: pre-earnings playbook MONITOR cards show "Re-evaluate after earnings ({date})"; Watchlist HOLD_OFF_EARNINGS cards show "Re-evaluate after {date}" computed from earn_days**

## Improvements (high value, not blocking)

### I1 — Home page cognitive overload — 8+ major sections
- **Location**: Home (`app.py`)
- **Problem**: Before scrolling: 3 KPI metrics, price strip, spinner, Pre-Market Intel, Act Today, Grow Today, More Buy Candidates, Protect Mode, Holdings Earnings — 8–10 distinct decision surfaces competing for attention simultaneously. Density above 5 distinct priority levels degrades decision quality.
- **Recommendation**: Collapse lower-priority sections (Macro Regime & Outlook, Advanced Risk Metrics, Diversification Advisor, Concentration Analysis) behind expanders that are **closed by default**. Keep Act Today, Protect Mode, and Grow Today expanded. The existing expander pattern is already in use — extend it consistently.

> **Deferred — not yet addressed (lower priority; Home already has tab/lane structure reducing density)**

### I2 — "User Guide" misplaced in ALERTS nav group
- **Location**: Sidebar navigation (`app.py` — nav structure)
- **Problem**: User Guide sits in ALERTS alongside Catalyst Watch and Economic Calendar. A first-time user looking for help will scan for a "Help" item, not under "Alerts." This is a wayfinding failure for the most onboarding-critical page in the app.
- **Recommendation**: Move User Guide to the bottom of the MAIN group, or create a standalone entry below a separator. The 📖 icon already differentiates it from alert icons (🔔 📅).

> **Resolved `2f58caa` — User Guide moved from ALERTS to MAIN nav group**

### I3 — Inconsistent severity scales across pages
- **Location**: Economic Calendar (`app.py`), Risk Advisor (`risk_advisor.py`), Watchlist Advisor (`watchlist_advisor.py`)
- **Problem**: Three different severity scales in active use:
  - Economic Calendar events: PROTECT / WATCH / OPPORTUNITY / HOLD
  - Risk Advisor cards: HIGH / MEDIUM / OK (red/amber/green)
  - Watchlist Advisor: ENTER_NOW / NEAR_ENTRY / WAIT_ENTRY / WAIT_CATALYST / HOLD_OFF_EARNINGS / REMOVE
  A user who has learned HIGH = red = urgent arrives at the Economic Calendar and sees "PROTECT" — is that more or less urgent? The color may match but the words do not map.
- **Recommendation**: Ensure the **color-severity mapping is consistent** across all pages: red always = act today, amber always = watch, green always = no action needed. Keep distinct vocabulary where meaning genuinely differs, but document the mapping in the User Guide.

> **Resolved `472af4f` — new "🚦 Signal severity — what the colors mean" expander added to User Guide mapping all five pages' vocabularies to the red/amber/green bands**

### I4 — Analysis page — 11+ expanders per ticker is high-friction for daily use
- **Location**: Analysis page (`app.py` — Detailed Analysis tabs)
- **Problem**: Each ticker tab contains up to 11 expanders (Technical Analysis, Fundamental Analysis, Sentiment & News, Price Targets, Risk Assessment, Performance & Attribution, Risk-Adjusted Metrics, Stress Test, Relative Strength, Sector Rotation Fit, Catalyst Watch). For a daily user who needs one number (e.g., current stop level), reopening all expanders is friction. The Summary Scorecard is not visible while inside a ticker tab — user has scrolled past it.
- **Recommendation**: Pin the scorecard strip (Price | Score | Stop | R:R) as a sticky sub-header within each ticker tab, or move it inside the tab. Alternatively, make the first expander ("Trade Plan") open by default and the rest closed.

> **Resolved `af8ba9c` — Note: the app already uses a 4-tab layout (Trade Plan / Chart / Risk / Deep Dive), not sequential expanders; the first expander within Trade Plan ("Key Support & Resistance") is now open by default**

### I5 — "Recommendations History" has no link back to current Analysis
- **Location**: Recommendations History page (`app.py`)
- **Problem**: A user who sees a past recommendation for NVDA with a 12% return cannot one-click to the current Analysis to check if the thesis still holds. The page is an audit trail with no forward navigation.
- **Recommendation**: Add an "▶ Analyze now" button in each table row (navigate to Analysis page with that ticker pre-populated). One line of code; closes the critical learning loop.

> **Resolved `2f58caa` + `608aba1` — jump-to-analysis widget (selectbox + "▶ Analyze {ticker}" button) added below the history table using `_pending_page` / `_analysis_ticker` pattern; caption added for discoverability**

### I6 — Watchlist "Readiness %" is unexplained inline
- **Location**: Watchlist page (`app.py`, `watchlist_advisor.py`)
- **Problem**: Expander headers read: `"✅ ENTER_NOW · NVDA | Score 78/100 · Strong Buy | Readiness 94%"`. "Readiness" is a new concept introduced here with no inline definition. Users will either ignore it or misinterpret it.
- **Recommendation**: Add a `help=` tooltip to the readiness metric: `"Percentage of buy criteria currently met (price in zone, score, trend, R:R, sector fit)."` Single parameter addition to the existing `st.metric` call.

> **Resolved `2f58caa` — st.caption added at top of each Watchlist expander body explaining Readiness % criteria**

## Quick Wins (under 30 minutes each)

- **Spinner text cleanup**: `"Checking for unaccounted stock splits…"` → `"Checking for splits…"`. `"⚡ Live snapshot — full analysis loading below…"` → `"Loading full analysis…"` (bolt emoji implies speed that may not match cold load reality)
- **"▶ Analyze" button label inconsistency**: Home uses `"▶ Analyze {ticker}"`, Scanner uses `"▶ Analyze"`, Analysis page uses `"▶ Full Analysis — {ticker}"`. Standardize to `"▶ Analyze {ticker}"` everywhere.
- **FMP latency label missing**: Price strip labels "Finnhub (real-time)" and "Yahoo Finance (15-min delayed)" but "FMP" has no latency context. Add "(end of day)" or "(15-min delayed)."
- **"More Buy Candidates" has no caption**: Add one-liner: `"Scanner picks not yet in your portfolio — run full Analysis before entering."`
- **Compare page empty state has three variations**: Consolidate to one: `"Enter two tickers and click ⚖️ Compare to see a side-by-side analysis."`
- **Delete icon on Account flow ledger is icon-only**: `🗑️` with no label on the cash-flow table. Add tooltip or label — icon-only destructive actions are an accessibility failure.
- **"🔄 Rebuild holdings & realized P&L" expander in Trade Journal**: Rename to `"⚠️ Fix drift between trades and holdings"` — aligns with the drift warning that appears above it and is scannable at a glance.
- **Account page baseline onboarding block looks like a status message**: `st.info("Set a starting baseline…")` uses the same blue style as informational status messages. Visually distinguish first-run prompts (e.g., bordered `st.container`) from ongoing status.
- **"↔ Steady vs yesterday" chip**: Add `help=` tooltip: `"Position status unchanged from the previous trading session."` — "vs yesterday" can confuse on weekends/holidays.

> **Resolved `f38e056` + `2f58caa` — all Quick Win items addressed: spinner text shortened, "▶ Analyze {ticker}" standardised, FMP label gains "(end-of-day)", More Buy Candidates caption added, Compare empty states consolidated, Rebuild expander renamed, Steady chip tooltip standardised. Remaining: Account delete icon already has `help=` tooltip (lower-priority visible-label improvement not yet done).**

| PROTECT / WATCH / OPPORTUNITY (Economic Calendar) vs HIGH / MEDIUM / OK (Risk Advisor) | Eco Cal, Risk Advisor | Align color-severity mapping; keep words different only if meaning genuinely differs |
