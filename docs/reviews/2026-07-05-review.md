## 1. Executive summary

The two contradiction fixes are architecturally correct — they apply the right pattern (Brief publishes reduce state, downstream surfaces read it) and the core suppression logic is sound. No critical or high-severity defect was found; no gate, threshold, score, or verdict logic is affected.

Five findings survived verification, all display/quality:

- **F1 (Med):** The Analysis reduce/exit banner extracted `_rc.get("action")` and used `isinstance(str)` to pick a label, but review-origin trim items carry `action` as a dict (`{"type": "TRIM_TO_TARGET", ...}`) — so the label always fell back to the generic "Reduce / Exit" for that item class. Deterioration items (string action) worked correctly.
- **F2 (Med):** The Opportunities KPI strip counted only `_ni_opps`, so when all qualifying holdings were suppressed the tile read "0 / no delta" while the amber banner immediately below named those same tickers — the two surfaces contradicted.
- **F3 (Low):** The amber "NOT SHOWN AS ADDS" note said "also have positive news" regardless of whether any green opportunity cards were shown above. When `_ni_opps` is empty the word "also" has no antecedent.
- **F4 (Low / efficiency):** `reduce_call_tickers(act_today, review_list)` was called in the News Intelligence block ~340 lines after `reduce_call_items(act_today, review_list)` had already published the identical set to `_reduce_calls`. Both internally call `split_defensive`. The fix derives `_opp_reduce_tickers = set(_reduce_calls.keys())`, consistent with the CLAUDE.md coordination rule (downstream features read, don't recompute).
- **F5 (Low / dead code):** The `isinstance(_daily_brief, dict)` ternary guard was unreachable — `_daily_brief` is unconditionally a dict by that point (either from the build or the offline `{}` literal). Eliminated as a side-effect of F4.

**Refuted candidates (not reported):**
- `_is_reduce` AttributeError risk: the `_source` discriminator ("act" vs "review") ensures each branch only touches the field format that stream actually uses — no cross-contamination is possible.
- `r['total']` TypeError in the under-reduce banner: a Buy/Strong-Buy Trade Plan only renders when the fundamentals gate passes and a scored composite exists; `r['total']` is always a float in that context.
- `classify_bucket` same action-dict vulnerability: same reasoning as `_is_reduce`.

## 2. Findings detail

### F1 — `_rc_label` wrong for review-origin reduce items (`app.py:11658`)

**Before:**
```python
_rc_label = _rc_action if isinstance(_rc_action, str) else "Reduce / Exit"
```

**After:**
```python
if isinstance(_rc_action, str):
    _rc_label = _rc_action
elif isinstance(_rc_action, dict):
    _rc_label = _rc_action.get("type", "Reduce / Exit")
else:
    _rc_label = "Reduce / Exit"
```

**Why it mattered:** `reduce_call_items` returns the review-origin TRIM item when it is the winning (first) reduce call per ticker (review-origin trims land in the Act bucket, before the Aware bucket in iteration order). In that case `_rc_action` is a dict, `isinstance(dict, str)` is `False`, and the banner always said "Reduce / Exit" instead of "TRIM_TO_TARGET" or "TRIM_AND_TIGHTEN". Act-origin deterioration items (string `"REDUCE — Deterioration Exit"`) were unaffected.

---

### F2 — Opportunities KPI tile undercounts when names are suppressed (`app.py:6270`)

**Before:**
```python
_nic4.metric("📈 Opportunities", len(_ni_opps), ...)
```

**After:**
```python
_ni_opps_total = len(_ni_opps) + len(_ni_opps_supp)
_nic4.metric("📈 Opportunities", _ni_opps_total, ...)
```

**Why it mattered:** When every qualifying holding was under a reduce call, the tile read "0 / no delta" while the amber banner immediately below named those tickers as positive-news candidates. The strip contradicted the section — a user scanning KPIs would think there were no opportunity signals at all.

---

### F3 — "also" copy wrong when `_ni_opps` is empty (`app.py:6354`)

**Before:**
```python
f"<b>{_supp_names}</b> also have positive news, but they're under a "
```

**After:**
```python
f"<b>{_supp_names}</b> {'also have' if _ni_opps else 'have'} positive news, but they're under a "
```

**Why it mattered:** "also" implies prior green cards were shown above. When `_ni_opps` is empty the section header renders but no cards follow, so "also" had no antecedent — a new reader would be confused.

---

### F4 — Redundant `split_defensive` call (`app.py:6234`)

**Before:**
```python
_opp_reduce_tickers = (
    reduce_call_tickers(_daily_brief.get("act_today"),
                        _daily_brief.get("review_list"))
    if isinstance(_daily_brief, dict) else set()
)
```

**After:**
```python
_opp_reduce_tickers = set((st.session_state.get("_reduce_calls") or {}).keys())
```

`reduce_call_tickers` also removed from the import. **Why it mattered:** `reduce_call_items` was already called ~340 lines earlier and published its output to `st.session_state["_reduce_calls"]`. The `reduce_call_tickers` call re-ran the full `split_defensive` bucketing pass on the same data. The fix follows the CLAUDE.md coordination rule ("downstream features read and gate") and makes the Overview and Analysis page consume the same published cache rather than independently recomputing.

---

### F5 — Dead `isinstance(_daily_brief, dict)` guard (eliminated by F4)

The ternary `... if isinstance(_daily_brief, dict) else set()` was always-true: `_daily_brief` is set to a dict literal in the offline path and returned as a dict in the online path. Eliminated as a side-effect of rewriting the block for F4.
