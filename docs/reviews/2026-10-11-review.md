## 4. High-priority issues

**B-H1 — The cron/email path never applies the sold-today block. ACTIVE.**
`stock_analyzer/headless_alert_engine.py:629-637` calls `build_daily_briefing(...)` with no `trades_df=` argument, although `ctx["trades_df"]` is loaded (`:116`, `:200`) and used at `:671`. The app passes `trades_df=st.session_state.get("trades_df")`. With `trades_df=None`, `_sold_today` (`daily_briefing.py:3536-3549`) is empty, so `_act_blocked |= sold_today` (`:855`) never runs on the cron path.
**Why it matters:** the scan lane (`cron_runner.py:1569`, 09:45 ET) can email "#1 ENTRY TODAY: buy X" for a name sold at 09:35, and persists it as a `new_pick` row — contaminating the Engine Track Record that the A2 offense analysis depends on. The intraday lane (`:1820`) has the same gap, and so does this window's ETF "acted-on-today sibling" screen-out (`daily_briefing.py:1494-1546`), which F-288 says covers a same-day sibling sale. No special data condition is needed: an ordinary morning sell triggers it.
**Fix:** pass `trades_df=ctx.get("trades_df")`, and add a parity test asserting the cron passes every `build_daily_briefing` kwarg that changes `_act_blocked`. `headless_alert_engine.py` is in `_GATE_FILES` → Opus review required.

**B-H2 — Brief Lock can freeze a crashed Brief into a day-long false all-clear. Rare trigger, severe consequence.**
The Lock button is disabled only when `_daily_brief is None` (`app.py:7699`), but the crash path has already replaced it with a stub dict (`app.py:6327-6333`), so Lock is clickable on an offline Brief. On the next run `_brief_use_lock` (`:6258-6264`) requires only `_brief_snapshot is not None`, serves the stub, the `if _daily_brief is None` branch is skipped, and the success branch sets `_daily_brief_offline = False`.
**Why it matters:** `act_today_view` then reports "clear" — Home's pointer reads "✅ Nothing to act on today" — and every reduce/exit veto disappears until unlock or the next trading day. This is the exact bug class P0 (`059a664`) said it closed.
**Fix:** disable Lock when `st.session_state["_daily_brief_offline"]` is true; and either store the offline flag inside the locked snapshot or refuse to serve a snapshot lacking `grow_today["tone"]`.

**C-H1 — `pre-commit` tests the working tree, not the staged index, with no warning. Proven by execution.**
`.claude/hooks/git_hook_adapter.py:402-444`: the pre-commit branch reads the staged file list, then runs pytest and the antipattern scan against files on disk. The tree-mismatch check (`_push_tree_mismatch`, `:441`) is called for pre-push only. Proven in a scratch repo: (1) stage a broken file, fix it on disk unstaged → "pytest PASSED", broken version committed; (2) stage a test importing an **untracked** module → "pytest PASSED", module absent from the commit.
**Why it matters:** case 2 is an `ImportError` in production, since Railway auto-deploys from `main`. CLAUDE.md attributes the working-tree limitation to `pre-push` only and describes `pre-commit` as running "the full pytest suite", which reads as gating the commit.
**Fix:** run pytest against `git checkout-index -a --prefix=<tmp>/` using the inherited `GIT_INDEX_FILE`. Minimum: call `ptc._tested_paths_dirty(include_staged=False)` before the run and print the MISMATCH warning. Either way, correct CLAUDE.md. Hook files are in `_GATE_FILES` → Opus review required.

**A-H1 — The Structural Scan saves G-25's baseline from an unverified matrix, and can permanently silence G-25. Latent.**
`app.py:18716-18728` builds `_ss_clusters` from `_corr_df_cache` with no coverage check; `app.py:18790-18796` saves it via `db.save_structural_scan_cache(cluster_snapshot=...)`, which becomes G-25's baseline — and saving is also what lifts live G-25 pauses (`:18803`). Proven by execution: below 20 shared observations the matrix yields spurious ±1 correlations (at `n_obs=5` a danger-tier pair appears). A scan saved on such a day records a fake cluster; on a later full-data day with a genuine 0.9 pair, `detect_new_clusters_strict` (`structural_scanner.py:330-358`) returns `[]` and G-25 never fires.
**Why it matters:** a gate failing open **through a persisted record** — precisely what "records withhold" exists to prevent. (The reverse — an all-NaN day saving an empty snapshot — is conservative and harmless.) On CLAUDE.md's known-open list; still open.
**Fix:** gate the Generate button and the save on `portfolio.correlation_claim_verified(_corr_unchecked_cache, _corr_coverage_cache)`, with a visible caption.

**A-H2 — `PAIR_RISK` trim cards can issue a SELL from 2–19 observations. Latent.**
`portfolio.py:2101-2143` performs no coverage check; `app.py:15267-15290` renders "Consider trimming X" with no disclosure. Proven: `n_obs=2` produced three trim cards, `n_obs=3` and `n_obs=5` one each. It is the only surface in the set that recommends a sale off an unverified matrix.
**Coupling the fix must handle:** F-294 deliberately keeps G-26's thin-day map alive *because* the `PAIR_RISK` card shows a trim from the same `risk_pairs` (`pair_add_gate.py:175-192`). Withholding `PAIR_RISK` on thin samples flips G-26's `trim_call` to `not_named`, and `describe_reason` (`pair_add_gate.py:236-240`) would then wrongly blame "a fund, or a data outage". Both must change in one reviewed commit.

## 8. Systemic observations

1. **The correlation sequence fixed instances, not the class.** Seven commits each patched one consumer of `_corr_df_cache`, and the patched ones now agree. The unpatched ones — Structural Scan, `PAIR_RISK`, Health Score, three narratives, two screens, Hidden Same-Bet — are the predictable residue of working surface-by-surface without first enumerating every reader. **Before the next fix in this area, enumerate every consumer of `_corr_df_cache` and classify each as screen or record.**
2. **App↔cron parity is unpinned.** B-H1 (`trades_df`), B-M7 (news inputs) and the missing block maps are three instances of one shape: the two paths call the same `build_daily_briefing` with different kwarg sets, and nothing asserts they match. A single parity test would catch the whole class.
3. **The "prefer a new module" convention pushes decision logic out of the gated set.** CLAUDE.md recommends extracting into a *new* module rather than growing a `_GATE_FILES` one, to keep extraction cheap. It works — and it means new decision modules (C-M6) start life ungated. The gradient that keeps extraction cheap is the same one that keeps enforcement honor-system.
4. **Several gates check a proxy rather than the thing.** The citation regex checks a string shape, not that the model was Opus (C-M2); FIX-FIRST passes as final (C-M3); `feat (` evades the trailer check (C-M4); `pre-commit` checks the working tree, not the commit (C-H1). CLAUDE.md already states the honesty caveat; these are concrete, cheap-to-close widenings of it.
5. **The thin-sample predicate exists in five copies, not three** (`pair_add_gate.py:56-74`, `cluster_add_gate.py:33-48`, `util.py:986-994`, `app.py:16099`, `app.py:17856`, plus its complement in `portfolio.py:1537-1540`). They agree on every integer but **disagree on `corr_coverage=None`**: four read it as "not thin", the shared verifier reads it as "unverified". Unreachable on Home today; still the right place to settle `None` semantics and the `numpy.int64` type together (see `docs/plans/pair-add-gate.md` §11.6).
